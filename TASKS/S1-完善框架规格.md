## 1. T1：D0 浏览器原型（决策门，最重要）

- 在 `webContentsView.ts` 实现 `createWebContentsViewAdapter(opts?: { devtools?: boolean }): BrowserAdapter`（接口见 `src/browserAdapter/types.ts`，**不允许改接口**）：
  - 实现方式：main 进程 `WebContentsView`（Electron 官方推荐，替代 `<webview>`）；navigate→`webContents.loadURL` + dom-ready 等待；snapshot→`executeJavaScript` 抓取可访问性近似（body.innerText + 可交互元素编号列表，元素编号优先于坐标）；click→按编号 `document.querySelectorAll('[data-loops-el]')` 或 CSS 选择器命中后 `el.click()`；type→focus + 逐字派发 input 事件；scroll→window.scrollBy/To；screenshot→`webContents.capturePage()` 转 base64 PNG；wait→setTimeout；executeJs→`executeJavaScript` 返回 JSON-safe 值；close→销毁 view。
  - 注入脚本（导航后注入）给元素标 `data-loops-el` 编号（`document.querySelectorAll('a,button,input,select,textarea,[role=button]')`）。
- 新增 `packages/shell/dev/d0-probe/`：最小 Electron 入口（electron 主文件，仅此目录允许 import electron）：
  - 创建 `BaseWindow` + 挂一个 WebContentsView + 另挂宿主页（data: URL 显示验证状态）；
  - 依次执行：navigate(data:text/html 含一个按钮) → snapshot（断言含按钮编号）→ click 按钮（断言页面状态变化）→ screenshot（写 PNG 到 `dev/d0-probe/shot.png`）→ executeJs 求和 → 打印结果、exit 0/1；
  - 说明：这是 D0 决策门的最小验证（第三方站点由用户后续手动过一遍）。
- 产出报告：实现要点 + probe 输出 + 「13 个 browser 工具复用/改造/重写」三档清单（按 slime 13 工具逐一评估，写进 `dev/d0-probe/TOOL-TRIAGE.md`）。
- 允许：本地重新 `pnpm install`（不带 ELECTRON_SKIP_BINARY_DOWNLOAD，下载 Electron 45 二进制）以跑 probe；跑完允许留 node_modules。

## 2. T2：LLM 真客户端（OpenAI 兼容）

- `packages/core/src/llm/openai.ts` 新增 `createOpenAiClient(opts: { platform: LoopsoarPlatform; baseUrl: string; apiKey?: string; model: string; }): LlmClient`（LlmClient 接口在 `llm/index.ts`，不改）：
  - `invoke` 用 `platform.net.fetchText` 不好做流式——因此**在 openai.ts 内用全局 fetch 实现 SSE 流式**（platform.net 只用于 resolveIps 的 SSRF 预检，可选注入）：
  - POST `{baseUrl}/chat/completions`，`stream: true`，逐行解析 `data: {...}`（`[DONE]` 结束），产出 LlmChunk：delta.content→text、reasoning_content→reasoning、tool_calls 增量→tool_call、usage→usage、结束→done；
  - 非流式误返回兜底（body 是完整 JSON 时转成一次 text+done）；错误响应（4xx/5xx）→ `{kind:"error", message}`；
  - 重试骨架：网络错误/5xx 退避重试 [1s,3s,7s] 最多 3 次；首包 120s 超时（AbortController）；**Retry-After 截断 60s**；
  - `normalizeUsage` 读 `prompt_tokens_details.cached_tokens` 与 deepseek `prompt_cache_hit_tokens` 归一到 `{prompt,completion,reasoning,cacheRead}`。
- `llm/index.ts` 末尾追加：`export { createOpenAiClient, normalizeUsage } from "./openai.js";`（只追加）。
- 单元测试由 T6 写。

## 3. T3：ChatService 真接线 + shell chat 域接通

- `services/src/chat.ts`：在现有 ChatService 上补全 `stream`：
  - 输入补充 `llm: LlmClient`（从 opts 注入）与 `platform`、`registry`（ToolRegistry）、`sandbox`（SandboxManager）、`agent: { name: string; role: string }`（ChatInput 扩展，兼容旧字段）；
  - 流程：buildSystemSegments(agent) → ModelRouter（可选注入，无则直连 llm）→ runToolLoop（executeTool = InternalToolExecutor：sandbox.checkPermission → allow 直接执行 registry.get(tool)?.execute；confirm/deny 走 PermRequestBus.request()（300s 超时按拒绝，返回可读拒绝文案））→ 每轮 `auditClaims(text, platform.fs.exists)` 结果附进 done 事件 → 事件经 EventNormalizer 归一 → sink/batcher；
  - 保持现有导出名不变（ChatStreamResult 等），**只补实现、不删签名**。
- `shell/src/main/domains/chat.ts`：把占位替换为真实接线（仍依赖注入，不 import electron）：

## 4. T4：插件宿主 + Agent-Loop 可插拔 + 安全模式后备（ADR-0010/0011 骨架）

- `core/src/plugin/manifest.ts`：`PluginManifest`（name/version/description/origin: builtin|user/agent、provides: 数组（tools|skills|loop|mode|settings|ui|page|views|theme|css|scripts）、requires、contributes 白名单校验函数 `validateManifest(m): string[]`（返回错误列表，空=合法）、禁自引/未知键拒绝）。
- `core/src/plugin/host.ts`：`PluginHost`：`load(manifest)`（拓扑排序 requires，环→failed）、`unload(name)`（逆序 dispose，幂等，单失败不阻断）、`registerTools` 挂点：`toolsProvider(name): ToolDefinition[] | null`（真实返回贡献，**不许返回空数组占位**——这是 slime 断点清单 B-4）；builtin 来源保护（isSystemRoot 的插件不得被 unload）。
- `core/src/plugin/scope.ts`：贡献点作用域：`register(contribution): { label: string; dispose(): void }`，卸载逆序 dispose。
- `core/src/loop/loopRegistry.ts`：**Agent-Loop 可插拔 + 安全后备（ADR-0010）**：
  - `LoopDefinition { id: string; name: string; builtin?: boolean; validate?: () => string[]; runner?: LoopRunner }`；`LoopRunner = (ctx: LoopRunContext) => Promise<ToolLoopOutcome>`（复用 core 的 ToolLoopOutcome）；
  - `class LoopRegistry`：`registerBuiltin(def)`（builtin 标记，**不可删改**：update 对 builtin 抛错，只能「复制为新 loop 再改」）、`register(def)`（静态校验：validate 返回错误即拒）、`run(id, ctx)`、`current(): string`、`switchTo(id)`；
  - **安全模式后备**：`run(id, ctx)` 包一层健康检查——①运行前 `validate` 失败→拒绝并回退 builtin；②执行中异常/崩溃→捕获→切回 builtin 用同 ctx 重跑一次（重跑期间 `safeMode: true` 传给 runner）；③超时/静默：用 LOOP_HEALTH.silentTimeoutMs 包裹 Promise.race（ctx 提供 heartbeat 信号由 runner 负责发，骨架只做超时判死）；④回退时 emit `safeModeTriggered` 回调（注入 `onFallback?: (reason) => void`）。**回退不丢 ctx（会话/工具结果保留在 ctx 里）**。
- `core/src/index.ts` 末尾追加：`export * from "./plugin/index.js"; export * from "./loop/index.js";`（plugin/index.ts 与 loop/index.ts 汇总各自目录导出，由本任务创建）。

## 5. T5：记忆五闸骨架 + 召回门控（ADR-0007 前置）

- `core/src/memory/fact.ts`：`MemoryFact` 数据模型（id/content/category/tags/importance(1-10)/timestamp/lastAccessed/links/backlinks/repeated/layer/accessCount/confidence/source/status/archivedAt/mergeTrail）。
- `core/src/memory/fiveGate.ts`（纯函数，阈值从 contracts 引入或与 contracts 对齐——若 contracts 没有这五个阈值，就在本文件定义并注明 ADR 出处）：
  - `jaccardCJK(a,b)`（中文单字+双字分片，不按空白分词——阈值校准教训）；
  - `gateDedupe(existing, incoming, threshold=0.75)`、`gateMerge(threshold=0.68)`、`gateLink(threshold=0.70)`、`gateCapacity(entries, max=2000)` → 最低 effectiveValue 者**软归档**（status=archived，**不物理删除**）；
  - `effectiveWeight(fact, now)` / `effectiveValue(fact, now)` 打分公式（指数衰减 τ=5.0、importance、confidence、repeated——按前期准备附录 B 公式）。
- `core/src/memory/recallGate.ts`：召回门控判据（**不调用 LLM 的廉价判据**）：`shouldRecall(text): boolean`——四信号：past_tense（上次/之前/那个/记得）、reference（这个/它/那个指代）、new_entity（专有名词/路径模式）、task_type 切换（由调用方传入上次任务类型比对）。
- `core/src/memory/index.ts` 汇总导出；`core/src/index.ts` 末尾追加 `export * from "./memory/index.js";`。
