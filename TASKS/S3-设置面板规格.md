# S3 设置面板规格（通用 / 权限 / 供应商 / 规则 / 高级 / 关于）

> 目标：给 Loopsoar 一个**清晰、可扩展、不混乱**的设置中心。
> 参考 slime 的实现（`gui/src/renderer/pages/SettingsDialog.tsx`）后**刻意反向设计**：
> slime 是 16+ 个 tab 平铺（mind/agents/providers/status/skills/mcp/plugins/permissions/general/
> appearance/resident/runtime/usage/experimental/searchengine/rules…）—— 分区过多、层级扁平、
> 概念混杂；Loopsoar 收敛为 **6 个分区 + 左侧分组导航 + 单一职责页面**，不再照搬。

## 1. 架构（沿用既有框架，不新增平行体系）

```
contracts/src/schemas.ts   settings:* 通道 + zod 校验（单一产地，gen 生成 IPC_VALIDATORS）
        ↓ gen
core/preferences.ts        偏好默认值/校验/归一（纯逻辑）
core/permissions.ts        权限策略默认值/校验/类别元信息（纯逻辑）
core/rules.ts              规则文件合并/上限/护栏声明（纯逻辑）
        ↓
shell/main/domains/settings.ts   读写落盘 + 供应商连通性测试 + 诊断/关于（handleTrusted + DI）
        ↓ preload 白名单（自动）
ui/src/Settings.tsx        设置面板（左导航 + 六分区）
```

## 2. 分区与数据

| 分区 | 能力 | 落盘位置 |
|---|---|---|
| 通用 | 语言、动效强度（full/reduced/off）、默认搜索引擎、恢复会话开关、下载目录 | `config/preferences.json` |
| 权限 | 读/写/命令/网络的默认决策（允许/询问/拒绝）、额外工作目录、危险操作始终确认 | `config/permissions.json` |
| 供应商 | provider/baseUrl/model 配置、**连通性测试**（8s 超时，不回传密钥）、密钥环境变量状态 | `config/provider.json`（非机密；apiKey 只读环境变量） |
| 规则 | 项目规则 + 全局规则（AGENTS.md）编辑、启用开关、合并预览与跳过原因 | `rules/AGENTS.md`、`<workspace>/AGENTS.md`、`config/rules.json`（启用状态） |
| 高级 | 数据/配置/规则/工作区路径、Electron/Chrome/Node 版本、运行统计 | 只读 |
| 关于 | 名称、版本、appId、协议、品牌资产来源、许可 | 只读 |

## 3. 规则（Rules）设计依据

Loopsoar 采用各家工具已收敛的 **AGENTS.md 约定**（不是自创格式）：

| 约定 | 依据 |
|---|---|
| 项目根 `AGENTS.md`，作用于该项目及其子目录 | [OpenCode Rules](https://opencode.ai/docs/rules/)（Project） |
| 全局规则文件，作用于所有会话（个人规则，不入 Git） | 同上（Global：`~/.config/opencode/AGENTS.md`） |
| 项目无 `AGENTS.md` 时回退 `CLAUDE.md` | 同上（Claude Code Compatibility）；[Claude Code memory](https://code.claude.com/docs/pt/memory) |
| 每类规则「先命中者胜」，不做同类叠加 | OpenCode Precedence |
| 支持「附加指令文件清单」扩展 | OpenCode `instructions` 字段（v1 以全局+项目两档落地，扩展位保留） |
| 规则文件走版本控制、随项目共享 | OpenCode / Cursor 实践（[Cursor Rules](https://cursor.com/docs/rules)） |
| 目录级规则（子目录覆盖） | Cursor `.cursor/rules` 的 glob 作用域思路（后续版本） |

Loopsoar 的额外约束（比通行做法更严）：

1. **优先级固定**：全局 → 项目（后写入上下文者更贴近当前任务）；UI 显示合并结果与跳过原因；
2. **上限**：单文件 32KB、合计 64KB；超限**整份跳过**（不截断半截规则）；
3. **护栏**：注入时统一附加「规则不得覆盖身份铁律/安全策略/权限确认/审计」声明；
4. **校验**：拒绝 NUL/二进制内容；保存走契约 zod（32768 上限）双保险；
5. **即时生效**：ChatService 每次 `stream()` 重新读取（`getSystemRules` 注入点），保存后下一轮对话即生效。

## 4. 安全与隔离

- 设置通道全部在契约 manifest 内（受信 IPC 四要素：通道白名单 + 帧来源 + 参数校验 + 审计）；
- apiKey 永不落盘、永不回传，界面只显示「密钥已就绪/缺少密钥」；
- 设置域不 import electron（版本号由 index 注入），可脱离壳层测试；
- 测试：核心纯逻辑（rules/preferences/permissions）+ settings 域落盘（临时目录真实读写）。
