# 记忆召回：原点图与混合检索方案

日期：2026-11-17；P0 实施：2026-11-19
状态：**P0/P1/P2 已实施（P2 含可选 LLM 重排已接入）**（见 §12）。回答两个问题：
1. 现在「以原点为中心分散」的记忆设计，是否已经对应到召回？
2. 如果不使用 embedding，如何把原点图的距离/激活与现有词法检索结合，形成 Loopsoar 的单栈方案？

## 0. 结论

**当前没有对应。**

- 原点图（origin / session / fact / L1 / L2 / L3）目前是**可视化模型**：buildMemoryGraph 生成节点与边，layoutMemoryGraph 按激活值决定半径，渲染层画图。
- 召回是另一套：recallPrompt 用 Jaccard + 实词 bigram 门控 + effectiveValue；memory_search 用 BM25 + hash 向量 + 融合分。
- 召回代码不读取图、不读节点半径、不读 session 归属、不走 links 扩展，也没有 memoryRanking = distance 这个配置。
- 原点设计文档第 4.5 节确实提出过「检索排序以距离为第一权重（0.75 activation + 0.25 similarity）」，但这一条**没有落地**。这是设计与实现的真实缺口，不是隐藏开关。

所以：**原点图现在帮助人看，不帮助机器找。** 要让「距离 = 优先使用」真正进入召回，需要一层独立的 MemoryRanker，把图的激活/层级/边接进检索。

## 1. 现状拆解

### 1.1 已落地的图

core/memory/graph.ts：

- origin：Loopsoar 本体，唯一中心；
- session：第一圈 L1，事实挂在所属会话下；
- fact：有存活会话的事实挂 L1；没有存活会话的进 L2；
- semantic 边：fact.links 两端都在图上才连；
- activation：有 usage 事件时按 ACT-R（R = Σ w·exp(-Δt/τ)，B = ln(1+R)，A = B/(B+1)），没有事件时回落到新近度 × 重要度；
- 布局：L1 / L2 / L3 三层环带，层内半径 = lerp(in, out, 1 - activation)，角度按会话稳定分配。

但：

- buildMemoryGraph 只生成 L1/L2 节点，L3 只保留 band 常量，没有实际 ghost/episode 节点；
- layoutMemoryGraph 的坐标只进 UI，不进检索；
- 图里的 semantic 边只用于画线，不用于召回扩展。

### 1.2 已落地的召回

自动注入 recallPrompt：

    score = effectiveValue(fact) * (0.2 + jaccard) + (tagHit ? 0.15 : 0)
    要求共享实词 bigram 或 tag 命中；只共享的/是不算相关
    过滤 score > 0.02；top 6

显式搜索 memory_search：

    BM25 候选 top 60
    → hash 向量余弦（256 维）
    → score = effectiveValue * (0.3 + jaccard + 0.5 * max(0, cosine)) + tagBonus
    → 过滤 0.08；top limit

effectiveValue 只关心「这条记忆值不值得用」：时间衰减、重要度、置信度、重复次数、显式访问次数。它不关心「这条记忆离当前会话/原点有多近」，也不关心图上的邻居。

### 1.3 结论

原点图与召回是**两条平行线**：

    图：activation → 半径 → 视觉距离
    召回：effectiveValue + 字面相似 → 排序

两者唯一共享的是「activation 与 effectiveValue 都含时间/使用因素」，公式不同、数据源也不同。

## 2. 原点设计原本想解决什么

设计稿第 4.5 节的意图是：

- 候选先过相似度最低门槛，只挡完全无关；
- 排序以 activation（距离）为主，similarity 只做并列打破；
- 最终分 = 0.75 * activation_norm + 0.25 * similarity。

这背后的假设是：**越靠近原点的记忆越可能被需要**，类似人类「常用的先想起来」。它适合：

- 用户说「上次那个」「之前说的」；
- 当前任务延续上一轮会话；
- 模糊指代、没有明确关键词。

但它**不适合**替代精确检索：

- 用户问「端口 8991 是什么」——需要精确匹配，不是最近常用的；
- 用户问「pnpm 约定」——字面命中比激活值可靠；
- 长期未用但唯一正确的事实，不能被「最近用过」压掉。

所以不能照搬 0.75/0.25 的纯距离排序；正确做法是**层内 hybrid，距离做先验，字面做资格**。

## 3. 目标方案：三层召回

### 3.1 第 0 层：硬过滤

先过滤，不参与打分：

- workspace 必须匹配（默认 default）；
- status = active，invalidated_at 为空；
- L3 ghost 默认不进入自动召回；只有显式提到、或用户点开时才 rehydrate；
- 时间范围、来源信任（web 记忆降权/标注）可选。

### 3.2 第 1 层：候选生成

候选来源可以并联，去重后最多 60 条：

1. 词法：BM25 / Jaccard，中文单字 + 双字，英文词；
2. 精确：实体名、路径、端口、命令、引号内容、tags；
3. 图扩展：词法命中的 fact，沿 links/backlinks 扩 1 跳（不扩 2 跳，防噪声）；
4. 会话先验：当前会话或最近会话产生的事实，轻微加权（不是硬命中）；
5. 层级先验：L1 > L2 > L3；L2 乘 0.85，L3 默认排除。

注意：图扩展只增加候选，不直接把邻居塞进上下文；最终仍要排序和限额。

### 3.3 第 2 层：混合排序

建议默认模式 hybrid：

    A = activation_norm（0..1，来自图/usage 事件）
    S = similarity（0..1，Jaccard 或 BM25 归一化）
    E = exact/tag 命中 ? 1 : 0
    G = 图邻居加成（0..1，命中节点的 1 跳邻居）

    score = 0.55 * A + 0.35 * S + 0.10 * E + 0.05 * G

可配置三档：

| 模式 | 公式 | 适用 |
| --- | --- | --- |
| similarity | 现有公式 | 精确查询、兼容旧行为 |
| hybrid（默认） | 0.55A + 0.35S + 0.10E + 0.05G | 大多数自动召回 |
| distance | 0.75A + 0.25S | 模糊指代/延续任务，需显式开启 |

约束：

- 候选必须先过「相似度最低门槛」或「exact/tag 命中」；不能只靠 A 高分把无关记忆排上来；
- A 只做先验，不做唯一资格；
- 自动注入 top 6；显式搜索 top 20；
- 输出带 reason（lexical / exact / graph / activation），便于调试和 UI 解释。

### 3.4 第 3 层：可选 LLM 重排

不引入 embedding，但可以用现有 API 大模型：

- 词法/图先捞 30–50 条候选；
- 把「查询 + 候选摘要 + 来源/时间」发给模型，让它选 top-6 并给理由；
- 失败/超时/无模型 → 回退 hybrid；
- 只在显式搜索或复杂查询触发，不每轮调用。

这符合单栈、无 Python、无 sidecar 的约束；1M 上下文模型做 30–50 条候选重排很轻松。

## 4. 原点元素如何进入召回

| 原点设计 | 当前用途 | 建议的召回角色 |
| --- | --- | --- |
| origin | 图中心 | 不参与打分；只是 workspace/agent 的作用域根 |
| session L1 | 图分支 | 会话先验：同会话事实轻微加分；不硬过滤 |
| fact L1 | 图节点 | 正常候选；A 来自 usage/新近度 |
| L2 游离 | 图外环 | 候选保留，乘 0.85 层级惩罚 |
| L3 失真 | 图外环（未实际生成） | 默认排除；显式提及才 rehydrate 进候选 |
| activation | 半径/大小 | 排序先验 A；不单独决定资格 |
| semantic 边 | 画线 | 1 跳图扩展 G；不递归扩散 |
| 稳定角度 | 空间记忆 | 只影响 UI；不参与召回 |
| usage 事件 | 图激活 | 同一套事件供 A 使用；自动注入不记事件（防反馈环） |

## 5. 激活值统一

图已经有一套 ACT-R 激活，建议召回直接复用，不再另造公式：

    使用事件：
      mention  用户明确提到       w=1.0
      tool     工具调用/选择       w=0.8
      search   memory_search 命中  w=0.6
      view     用户点开详情        w=0.3
      auto     自动注入            w=0（不计，防富者愈富）

    R = Σ w * exp(-(now - at) / τ)    τ=30 天
    B = ln(1 + R)
    A = B / (B + 1)
    A_final = A * (0.6 + 0.4 * importance/10)

没有事件时，回落到新近度 × 重要度（与图一致）。

注意：现有 effectiveValue 也含时间/访问，hybrid 里如果同时用 A 和 effectiveValue 会重复计权。建议：

- 召回排序只用 A + S + E + G；
- effectiveValue 继续用于容量淘汰/后台巩固，不在召回里二次相乘。

## 6. 结构与性能

### 6.1 新增纯逻辑

core/memory/ranker.ts：

    type MemoryRankingMode = "similarity" | "hybrid" | "distance";
    rankMemory({ candidates, query, mode, now, graph, usage }) -> RankedHit[]

输入是候选 fact + 可选的邻居表/激活快照；输出带 score 和 reasons。零 IO，可单测。

### 6.2 图索引缓存

不要在每次召回时重建整张图。维护一个轻量邻接表：

    factId -> { links, backlinks, sessionId, band, activation }

写入/使用事件变化时增量更新；召回只读。2,000–10,000 条规模，内存索引足够。

### 6.3 性能预算

- 候选生成：BM25 单遍扫描 2k 条 <5ms；
- 图扩展：1 跳，最多 60 条候选 × 平均 3 邻居；
- 排序：60 条 O(n log n)；
- 自动召回 P95 目标 <20ms（纯 JS，2k 条）。

## 7. L2/L3 与召回

当前图只实现 L1/L2；L3 是设计预留。召回方案要明确：

- L2：正常候选，乘 0.85；仍可自动注入；
- L3：默认不进入自动召回；显式搜索/用户提及/点开时 rehydrate 到 L2，再参与；
- 若 L3 原文已不可恢复，只能凭摘要/关键词参与，并标注「原始内容不可恢复」；
- 没有真实 L3 数据前，不要假装有；先把 L1/L2 的 hybrid 跑通。

## 8. 评测

### 8.1 离线

现有 docs 语料（237 小节）+ 新增三类用例：

1. 精确：端口/路径/命令，必须 lexical 命中；
2. 模糊：上次/之前/那个，必须 activation/session 先验帮忙；
3. 干扰：最近用过但无关 vs 久远但正确，hybrid 不能把后者压掉。

指标：

- recall@1 / recall@3 / MRR；
- 负样本 top score 与正样本 p10 的间隔；
- 模式对比：similarity vs hybrid vs distance；
- 延迟 P50/P95。

验收：

- hybrid 的 recall@1 不低于 similarity（允许 ±1 点）；
- 负样本间隔不低于现有；
- distance 只在模糊集上优于 hybrid，精确集不能下降超过 2 点。

### 8.2 在线

- 记录每次召回的 reason 和最终是否被使用（view/search），做后验；
- 自动注入不计 usage，避免自我强化；
- 每周抽样 50 条，人工标注相关性。

## 9. 分阶段落地

P0（只做纯逻辑与开关）：

- 抽 rankMemory，支持 similarity/hybrid/distance；
- 用现有 effectiveValue + Jaccard 复现旧行为，确保零回归；
- 单测覆盖三种模式。

P1（接图）：

- 图邻接/激活快照；
- hybrid 默认，similarity 回退；
- 自动召回与显式搜索共用 ranker，但 top-k 不同；
- 评测三种模式。

P2（L2/L3 与 LLM 重排）：

- L2 惩罚、L3 排除/rehydrate；
- 可选 LLM rerank；
- UI 显示命中理由（词法/图/激活）。

## 10. 风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 激活值主导 | 最近常用但无关的记忆压掉精确事实 | 相似度资格门槛 + hybrid 权重 + 精确集评测 |
| usage 稀疏 | 新记忆 A=0，永远排不上 | 新记忆给冷启动先验；importance 兜底 |
| 会话先验噪声 | 同一会话的无关事实被抬高 | 只做轻微加分，不做硬过滤 |
| 图扩展爆炸 | 邻居太多、上下文变长 | 只扩 1 跳、限额 60、邻居只参与排序不直接注入 |
| 双重计权 | A 与 effectiveValue 都含时间 | 召回只用 A，effectiveValue 留给容量 |
| workspace 泄漏 | 跨项目记忆进入召回 | 第 0 层硬过滤，测试覆盖 |
| L3 未实现 | 文档承诺了 ghost，实际没有 | 明确标注 L3 未落地；先不做 rehydrate |

## 11. 最终建议

1. 不要把当前的「原点图」当成已经参与召回；它现在只是可视化。
2. 也不要把召回改成纯距离排序；精确查询会被最近常用记忆污染。
3. 采用 **hybrid：相似度做资格，激活/距离做先验，图邻居做加成，可选 LLM 重排**。
4. 不引入 embedding；这套方案在纯 JS/Electron 单栈内可完成。
5. 先做 P0/P1，用 docs 语料 + 三类新用例做 A/B；没有评测通过前不要默认切 distance。

一句话：原点图给出的是「亲疏」，召回需要的是「亲疏 + 像不像」；两者接起来才是完整的记忆检索，而不是二选一。

- 新增 `packages/core/src/memory/ranker.ts`：`rankMemory` 支持 `similarity` / `hybrid` / `distance` 三档。
  - similarity 逐项复现 `store.recall` 旧公式：`effectiveValue × (0.2 + jaccard) + (tag ? 0.15 : 0)`，阈值 0.02；
  - hybrid / distance 按 §3.3 公式；带「相似度门槛或 exact 命中」资格、L2 ×0.85、L3 默认排除；
  - 无 usage 事件时用 `effectiveValue` 折算冷启动先验（§10 的「新记忆排不上」）。
- `MemoryStore.recall` 改为经 `rankMemory` 排序，新增可选 `ranking` 信号（mode / activation / graph / band / exact）；
  缺省 `similarity`，`recallPrompt` 行为不变。
- 新增 `detectExactHit`：引号内容、端口、路径、命令、tag 的精确命中判定。
- 单测 `tests/core/memoryRanker.spec.ts`（14 条）；P0 时点全量 248 文件 / 1931 用例、typecheck 全绿。

**P1 已完成**（2026-11-19）：

- `MemoryService.recallPrompt` 默认 `hybrid`：一次召回内共享 usage 快照，信号 =
  ACT-R 激活值（`activationOf`）+ 1 跳图邻居（仅词法命中事实的 links/backlinks）+ 层级；
- 层级：有存活会话（`setLiveSessionProvider` 注入）→ L1，无会话且 90 天未用 → L3，其余 L2；
  L3 默认被 ranker 排除，exact 命中才放行；
- `rankingMode` 可切 `similarity`（旧行为零回归）/ `hybrid` / `distance`；
- 评测（`node scripts/memory-eval.mjs --modes`，60 题 / 5 类）：similarity、hybrid、distance 均 **60/60**，
  P95 ≤ 0.21ms；hybrid 不比 similarity 差（方案 §8 验收线通过）。

**P2 已完成（除方案标注为“可选”的 LLM 重排）**：

- 显式搜索与自动召回共用 `rankMemory`：检索仍产出 BM25+向量候选，排序统一走 ranker，
  显式搜索关闭资格门槛、放行 L3（rehydrate 后参与）、top-k 更大；
- UI 命中理由：`store.recallDetailed` 返回 reasons，`MemoryService.lastRecallReasons()` 缓存最近一次自动召回，
  `memory:list` 下发，设置·记忆面板在条目上显示「词法/精确/激活/图邻居/L2」徽标；
- LLM 重排（方案标注为可选）已实现：`MemoryService.setReranker` 注入，只在显式搜索且候选数 > limit 时触发；
  8s 超时 / 无模型 / 报错 / 无法解析 → 回退 ranker 顺序（fail-open），自动召回不调用。
- `tests/shell/memoryRerank.spec.ts`（5 条）覆盖解析、fail-open 与集成。
