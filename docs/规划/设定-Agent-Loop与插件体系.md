# Loopsoar 最后设定：Agent-Loop 可插拔 · 万物皆插件 · 好用低门槛

> 定稿：2026-10-27（用户裁决的最终设定；对应 ADR-0010 / 0011 / 0012）
> 一句话：**对齐 DSH 的「万物皆插件」，保留 slime 的原定风格（本地优先、Agent 人格、内嵌确认），但把 Loopsoar 做成「即好用、门槛不高」的 harness——开箱即用，深度可拆。**

---

## 一、Agent-Loop：内置最小完备 + 彻底开放 + 安全后备

### 1.1 总原则

> **Loop 是一等公民：可插拔、可替换、可自定义。安全护栏属于 harness，不属于 loop。**

- 内置**只有一个**初始 Agent-Loop：最简、足够 Agent 正常完备运行（不多不少）；
- 用户可以选择不用它、修改它、自建全新的 loop；
- 无论用户怎么改，**安全护栏（§1.5）永远在 loop 外层强制生效**；
- 用户改坏 loop → 自动回退初始 loop（安全模式），**Agent 永远不会因此跑不起来**。

### 1.2 内置初始 Loop（minimal complete，MVP 的默认）

```
① 装配上下文：stable（身份铁律/诚实协议/技能清单）进 system；volatile（记忆召回/状态摘要）挂末段 user
② 模型推理：模型路由（云降级链/本地）→ 产出文本或 tool_calls
③ 工具轮：无 tool_calls → 终答；
          有 → 逐工具：权限判定（四层）→ 执行 → 结果回灌 → 下一轮 ②
④ 轮末后处理：每轮声称核验 → 记忆五闸写入 → 状态摘要 → 落盘
```

这就是 slime 引擎主循环的极简形态——只保留「跑起来并且跑得完备」所需的最小步骤，不内置任何花哨阶段（头脑风暴、批量编排等全部作为可选扩展）。

### 1.3 自定义 Loop 的三档深度（对应易用性分层 §三）

| 档 | 形态 | 用户是谁 | 交付物 |
|---|---|---|---|
| **L1 参数化** | 不改结构，只调参：轮次/预算/注入段/工具面档位/模型策略 | 进阶用户（设置面板即可） | 设置面板 + 预设集 |
| **L2 声明式** | 复制内置 loop 为「我的 loop」，以 JSON/YAML 声明流水线（stages/hooks：think/tool/observe/verify/memory…）微调 | 熟练用户 | 可视化编辑器 + 校验器 + 预览 |
| **L3 脚本式** | 完整自由：TS/JS 钩子（onRoundStart/onToolResult/onFinish…）或整段 loop 脚本，经插件 `loop` 贡献点装载 | 开发者 | 插件 SDK + 模板 + 沙箱 |

### 1.4 安全后备（防改坏，MVP 必须）

- 内置 loop 标记 `builtin`：**不可删除、不可原位修改**，只能「复制为新 loop 再改」——原件永远是最后兜底；
- **启动前静态校验**：语法 / 引用完整性 / 清单合法 → 失败则拒绝启动该 loop，显示诊断，回落内置 loop；
- **运行期健康检查**（harness 层，任何 loop 都逃不掉）：
  1. 心跳超时（工具执行期无 heartbeat / loop 无任何事件）
  2. 预算四闸（安全护栏，§1.5）
  3. 异常/崩溃（loop 抛错、进程退出）
  4. 空工具面 / 空回复死循环（连续 N 轮无进展）
- 触发任一 → **安全模式**：自动切回内置 loop 跑完当前任务，界面显著提示「已回退初始 Agent-Loop，原因：X」，附诊断报告 + 一键修复入口；
- **回退不丢数据**：会话、工具结果、记忆写入全部保留，切回后任务继续而非重来。

### 1.5 不可自定义的安全护栏（loop 无权触碰）

| 护栏 | 归属 | loop 的权限 |
|---|---|---|
| 权限四层 + fail-closed | harness | 只能请求，不能自授；会话白名单仍由用户点 |
| 四道预算闸 | harness | loop 可收紧，**不可放松到超硬上限**（硬上限 harness 定） |
| 每轮声称核验 + 强制工具轮 | harness | 不可关闭 |
| 身份注入（author 等参数不可覆盖） | harness | 不可伪造 |
| 心跳协议 | harness | 自定义 loop **必须实现心跳**，不实现按静默超时 → 回退 |
| Git 治理（若启用） | harness | 不可绕过 |

## 二、扩展系统：万物皆插件（对齐 DSH，给用户最大自由度）

### 2.1 内核最小化

**harness 内核只留四件**：浏览器壳 + 引擎 + 安全护栏 + 插件宿主（PluginHost）。其余**全部**以插件形态存在——包括内置功能。

- 内置功能 = **builtin 插件**（默认开启，可禁用、可替换）；只有「内核四件 + 内置初始 loop」不可卸载；
- 对比 slime：31 组内置插件 `unloadable:false` 钉死 → Loopsoar 只钉内核，其余全可动；
- 用户的插件可以覆盖/替换 builtin 插件的任何贡献（贡献点冲突按声明优先级裁决，裁决可见）。

### 2.2 贡献点（slime 八类 + 新增，全部开放）

| 贡献点 | 说明 | 继承自 slime / 新增 |
|---|---|---|
| `tools` | 注册新工具进同一注册表（**registerTools 真实现**，补齐 slime 断点；插件工具权限 = 插件声明权限 ∩ 会话授权） | 继承（修复后） |
| `skills` | Markdown 指令层 | 继承 |
| `mode` | 阶段机（每段可限工具白名单与轮次） | 继承 |
| **`loop`** | **Agent-Loop 定义（§一 L3）**——本次新增的最核心贡献点 | 新增 |
| `settings` / `ui` / `page` / `views` / `theme` / `themes` / `css` | UI 与外观全开放（用户可自由设计界面：面板/侧栏/工具栏/右键菜单/状态区） | 继承（UI 白名单区域扩充） |
| **`omnibox`** | 地址栏命令与来源（浏览器优先形态的自然贡献点） | 新增 |
| **`agent-template`** | Agent 预设（身份/人格/工具面成套打包） | 新增 |
| `scripts` | .mjs 一次性子进程（默认不信任，显式授权） | 继承 |

### 2.3 信任与撤销（沿用 slime 已验证机制）

trust.json fail-closed → PluginHost 拓扑装载 → 贡献点作用域（`{label, dispose}`）→ 逆序 dispose（幂等、单失败不阻断）→ 禁用名单。**发布门 4（插件权限生命周期端到端）不变。**

### 2.4 开发体验（低门槛的关键）

- 插件向导：选模板（工具/面板/loop/主题）→ 生成骨架 → 本地沙箱预览 → 热重载；
- 校验器：清单/贡献点/权限声明即时检查，错误给出可读原因与修复建议；
- 「把当前配置导出为插件」：用户调好的设置/loop/主题一键打包成插件，可分享（后续接市场）；
- 插件页面/视图一律沙箱 iframe + CSS 禁令表（继承 slime）。

## 三、易用性策略：好用 + 低门槛（不做「毛坯房」）

> DSH 被诟病「毛坯房、门槛高」；Loopsoar 的对策不是削弱自由度，而是**把自由度分层递进**。

### 3.1 三档使用深度（渐进披露）

| 深度 | 用户画像 | 看到什么 | 能力边界 |
|---|---|---|---|
| ① 直接用 | 普通用户 | 开箱即用：默认 loop + 默认插件 + 首次向导 + 内置示例技能 | 不改任何东西也能用得很好 |
| ② 改配置 | 进阶用户 | 设置面板：L1 参数化 loop、插件开关、主题、工具面档位 | 不动代码 |
| ③ 造东西 | 开发者 | L2 编辑器 + L3 脚本、插件 SDK、UI 定制 | 全自由度（对齐 DSH） |

默认 UI 只显示 ①；②③ 区域可展开，不挡道。

### 3.2 反「毛坯房」清单（写进验收）

1. 首次启动向导：模型配置 → 本地推理检测 → 示例技能 → 3 分钟可用；
2. 每个可配置项都有**默认值 + 中文解释 + 恢复默认**；
3. 所有错误提示**可读 + 给出下一步动作**（不许裸堆栈）；
4. 一键回退三件套：loop 回退（安全模式）/ 插件一键禁用 / 配置快照与恢复；
5. 产品内文档：设置项就地解释、loop/插件模板内嵌注释；
6. 可演示：非开发者 10 分钟内完成「搜索 → 抓取 → 出结论」的完整任务。

### 3.3 保留 slime 的原定风格（对齐 DSH 但不丢魂）

- 本地优先：数据落本地，Agent 是「你的」；
- Agent 人格与陪伴感：身份铁律、称呼连贯、不讨好也不冷漠（mind-lite）；
- 流式卡片、思考/工具折叠、输入框内嵌权限选择题、右侧栏、双主题——沿用 slime 的交互遗产；
- 可信自治：可见执行日志、敏感步骤确认、审计可追溯——这是 Loopsoar 与「AI 浏览器红海」的分野。

## 四、对既有规划/交付物的影响（同步修订点）

1. **MVP 验收表 §三**：新增「Agent-Loop 可插拔」必须项（内置 loop + 复制修改 + 安全模式回退；L3 脚本 loop 随插件系统后置）；
2. **规划 §6.2 处置表**：C 新增补「`loop` / `omnibox` / `agent-template` 三个贡献点」；D 削减项中「31 组内置插件 unloadable:false」改为「内核最小化，内置功能插件化可禁用」；
3. **规划 §6.3 里程碑**：P5 扩展阶段验收新增「loop 贡献点装载 + 安全模式回退演练」；P6 壳层验收新增「三档使用深度渐进披露 + 反毛坯房清单 6 条」；
4. **ADR**：新增 ADR-0010（Loop 可插拔与护栏归属）/ ADR-0011（万物皆插件）/ ADR-0012（易用性策略）。
