# MVP 验收表（Loopsoar 最小可交付版本）

> 定位：回答「什么必须真正跑通、什么可后置、什么测试不通过就不能进入下一阶段」。
> 口径：MVP = **一条完整主链路**（对话 → 模型调用 → 工具执行 → 权限判断 → 结果核验 → 记忆读写）在**浏览器为主界面的产品形态**下真实可用；24–30 周是初步估算，不是承诺——阶段出口以验收门为准。

---

## 一、最小可交付主链路（六步，全部必须跑通）

| # | 步骤 | 必须跑通（勾选标准） |
|---|---|---|
| 1 | 对话 | 用户在浏览器主界面的命令框输入（URL / 搜索 / 自然语言）→ 进入会话；流式渲染；停止/重试可用 |
| 2 | 模型调用 | 云模型路由（≥1 提供方，降级链可演示）；stable/volatile 前缀分离生效（日志可证前缀字节稳定）；四闸可触发并归因 |
| 3 | 工具执行 | 工具轮多轮执行；心跳事件；工具最小集可用：`web_search` / `web_fetch` / `browser_*`（导航/点击/输入/截图/滚动/等待）/ `file_read` / `file_write`（5MB 上限）/ `memory_*` / `todo_write` / `ask_user` |
| 4 | 权限判断 | 权限四层（L0–L5）+ 会话白名单 + 输入框内嵌确认（allow-once/allow-session/deny）；危险命令阻断；越界路径拒绝 |
| 5 | 结果核验 | **每轮**声称核验（7 类完成动词 + 路径/大小证据）；强制工具轮；失败带 `[错误]` 前缀不包装成功 |
| 6 | 记忆读写 | 记忆五闸写入（去重 0.75 / 跨 agent 指针 / 合并 0.68 / 建链 0.70 / 2000 上限 + 软归档）+ 四阶段检索 + 召回门控；会话内可回忆、新会话可查回 |

**验收口径**：六步在**真机端到端**（不是单测）全通；每一步的失败模式有可读提示；主链路可录制演示视频。

## 二、浏览器功能面（MVP 必须项，产品主体）

> 借鉴 slime 先例、不照搬代码；实现走 BrowserAdapter（D0 冻结接口，ADR-0003）。

| 功能 | MVP 必须 | 验收 |
|---|---|---|
| 多标签 + 标签组 | ✅ | 开/关/切/分组；每个标签独立任务空间（Agent 任务与用户浏览互不打扰） |
| 地址与搜索一体框 | ✅ | URL 直达 / 搜索词走自建多引擎；自然语言命令进 Agent |
| 页面操作 | ✅ | 元素定位点击、表单输入、滚动、截图、等待、JS 注入（browser_* 工具） |
| 下载 | ✅ | 下载管理、进度、落盘路径受权限层约束 |
| 书签 / 历史 | ✅ | 持久化、可搜索（复用记忆检索能力） |
| 广告拦截 | ✅ | 请求拦截等价物（webRequest/WebContentsView 会话拦截）生效可证 |
| 页面保存 | ✅ | 全文保存（页面消失内容仍在，Tabbit 形态参考） |
| 可见执行日志 | ✅ | Agent 的每次导航/点击/提取在界面可见，可追溯 |
| 敏感步骤确认 | ✅ | 登录态操作、支付、不可撤销操作必须人工确认（写死规则，不靠模型自觉） |
| 扩展系统 / 阅读模式 / 同步 | ⬜ 后置 | — |

## 三、Agent 引擎（MVP 必须项）

| 项 | 验收 |
|---|---|
| 引擎四件套 + 四闸 + 心跳 | 规划 §1.4 第 1–3 条原样继承，验收同 P1 |
| 反幻觉三层 | 每轮声称核验 + 强制工具轮 + 工具即事实源 |
| 身份与输出过滤 | 身份铁律 + 输出过滤 + 诚实协议 + **不过度附和**规则（mind-lite） |
| 身份包导出/导入 | `.loopagent` 包（继承 v1.2 协议）：导出 → 新环境导入 → 记忆/偏好/行为恢复可用 |
| 模型管理 | 云模型配置 + 本地 llama-server 基本拉起（CUDA/CPU 自动回落）；**MoE 适配继承**（字节口径估算 / KV 只算注意力层 / `--n-cpu-moe`） |
| **Agent-Loop 可插拔** | 内置初始 loop 完整运行（主链路六步即其体现）；用户可**复制修改（L2 声明式）并切换**；健康检查 + **安全模式回退**（改坏自动回退内置 loop，任务不中断、数据不丢，界面显示回退原因与诊断）；L3 脚本 loop 与可视化编辑器随插件系统后置 |

## 四、安全发布门（全部必须，P9 前五条全绿）

见规划 §6.4：①权限 fail-closed 行为测试 ②浏览器桥隔离（四攻击路径）③SSRF/DNS 钉扎/重定向 ④插件权限生命周期端到端 ⑤声称核验。**每条 = 反例 + 攻击输入 + 预期拒绝 + 自动化用例（ADR-0009）**。另：模型下载 sha256 校验进 MVP。

## 五、分发（MVP 必须）

Windows x64：安装版 + 便携版；自动更新（显式触发）；托盘/单实例；CUDA 运行时分层（增补包必须有代码去装）；崩溃自愈。

## 七、阶段门（什么测试不过就不能进入下一阶段）

| 门 | 卡点 | 未通过后果 |
|---|---|---|
| P0 → P1 | W1–W5 全绿（见 P0 验证计划总出口） | 不开工引擎迁移，逐线处置写 ADR |
| P1 → P2 | 引擎单测全绿 + 无壳 harness 完整工具轮 + 五问清单随迁齐全 | 回 P1 补测，不进入安全层 |
| P2 → P3 | 安全发布门 1、3 全绿；异常规则无空分支 | 卡在 P2（安全门不可跳过） |
| P4 → P5 | 10 万条检索延迟/质量达标（ADR-0007 固化阈值）；归档查回 100% | 记忆后端回退路径 |
| P5 → P6 | 插件装载→贡献→停用→撤销闭环 + 发布门 4 全绿 | 卡在 P5 |
| P6 → P7 | 主链路端到端（含权限弹窗与浏览器自动化）+ 发布门 2 全绿 | 卡在 P6（浏览器桥隔离不绿，不上多 Agent） |
| P8 → P9 | mind-lite 闭环读回 + 注入不污染 stable 前缀 + 无数值演化网络 | 心智降级为「仅记忆」，不发行为计数器 |
| P9 → 发布 | **发布门五条全绿** + 安装→更新→卸载三环境实测 + Electron 版本回归清单通过 | 不发布，逐条清零 |

## 八、v1 发布定义（一句话）

**一个 Windows 桌面的、以浏览器为主界面的 Agent：能搜索、能抓取全网数据、能在网页上替你干活，全程可见、可确认、可核验、可追溯，记忆与身份可导出带走——且五条安全发布门全部通过。**
