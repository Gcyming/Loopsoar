# 记忆图谱设计：原点 · 第一分支 · 游离层 · 失真层

> 状态：设计稿（未实现）。依据：用户口述模型（本轮）+ 全网调研（docs/research/agent-memory-survey.md）+ slime 复盘（docs/research/slime-memory-review.md）+ 我们现有代码（memory/、sessionStore、contextCompress）。
> 一句话：**把「记忆」从一个列表，变成一张以 Loopsoar 自身为原点、按激活强度分层环绕的星图；会话是第一圈枝干，删除的会话降为游离层，长期沉默的沉入失真层，提及即回升。**

### 0.2 术语与规则（逐条对照你的原话）

| 你的说法 | 我的理解 | 设计中的名字 |
| --- | --- | --- |
| 记忆原点，一切的中心 | 一个固定节点，代表 Loopsoar 智能体程序本身；不是数据，是坐标系原点 | origin |
| 第一层分支（硬性规定）散为不同会话及其内容 | 第一圈**只能**是会话节点；会话里的内容作为会话的子节点挂在它周围 | session（L1） |

| 会话被删除 → 压缩一次 → 成为游离层 | 删除时触发一次「会话摘要」（复用 contextCompress），产出一个 episode 节点，放到第二圈 | drift（L2） |
| 游离层按提及次数增减权重 | 提及越多越靠内；权重 = 频次 × 新近度 × 重要度（下面给公式） | activation |
| 失真层：长期未提及/未使用的会话或游离节点 | 第三圈；只保留高度压缩的边缘记忆（关键词 + 一句话 + 指针） | ghost（L3） |
| 除非用户主动提及，否则再无补充 | 失真层**只读、不自动更新**；被提及时才唤醒（rehydrate） | frozen until touched |
| 三者严格按调用次数决定距原点的远近 | 半径 = f(激活值)；层是离散的，层内连续 | radial mapping |
| 所有节点设置关联 | 每个节点至少有一条边；事实有来源边、语义边；会话有继承边 | edges |

### 0.3 三层各放什么（边界）

| 层 | 放什么 | 不放什么 | 压缩程度 |
| --- | --- | --- | --- |
| L1 第一分支 | 会话节点 + 该会话的代表事实（最多 N 条，其余放大后展开） | 别的会话的事实、已删除会话 | 无额外压缩（自然上下文压缩） |
| L2 游离层 | 被删除会话压缩成的 episode；被删除会话里提取出的高价值事实 | 未删除会话的事实 | 一次摘要（≤400 字）+ 保留事实条目 |
| L3 失真层 | 长期未提及的 episode / 事实；只留关键词、一句摘要、原始指针 | 完整正文 | 二次压缩（≤120 字）+ 关键词 |

## 1. 五个边界，我先给默认（你可以只改不同意的那条）

1. **未删除但长期闲置的会话怎么办？** 默认：会话节点**始终留在 L1**（它是硬性结构，不代表活跃度），但它的**事实节点**可以降到 L3。这样「第一层只放会话」的规则不被破坏，同时长期不用的内容会自然远离中心。
2. **失真层还保留原文吗？** 默认：不保留正文，只保留「关键词 + 一句摘要 + 指针（sessionId / factId）」。原始消息若还在磁盘（会话没删），唤醒时回取原文；若已随会话删除，唤醒只能凭摘要重建——这时 UI 要明确标「原始内容已不可恢复」。
3. **「提及次数」怎么记？** 默认三种，权重不同：用户在消息里明确提到（1.0）、模型 memory_search 命中（0.6）、用户点开节点详情查看（0.3）。每次记一条带时间戳的事件（用来算新近度），**不是简单 +1**。
4. **半径由「调用次数」还是「激活值」决定？** 默认：**激活值**。纯次数会让三个月前的爆款节点永远贴在原点，违反你「类似遗忘机制」的意图；激活值 = 频次 × 新近度 × 重要度，次数是其中一项。
5. **每个会话的每条记忆都上图吗？** 默认：不上。会话节点 + 最多 N=12 条「代表事实」（按激活值取），其余在放大/点击时展开。否则一个长会话就能炸掉整张图。

## 2. 认知科学依据（为什么这套模型不是拍脑袋）

### 2.1 激活与遗忘：ACT-R 的基础级激活

认知架构 ACT-R 用一个公式统一了「频次」与「新近度」（Anderson & Schooler, 1991）：

~~~
B_i = ln( Σ_j t_j^(-d) )        d ≈ 0.5
~~~

- t_j = 第 j 次被使用距今的时间（秒/天，统一单位即可）；
- 指数 d≈0.5 给出的是**幂律遗忘**，比指数衰减更贴近人类数据；
- 检索概率是 B_i 的 logistic 函数——也就是说「离原点越近越容易被想起」有模型基础，不是视觉隐喻。

**我们的用法**：把 B 归一化成 [0,1] 的 activation，既驱动半径，也驱动检索排序（与现有 effectiveValue 合并）。

### 2.2 扩散激活：为什么「所有节点设关联」是对的

Collins & Loftus (1975) 的扩散激活模型：一个概念被激活后，激活沿语义链接向邻居扩散并随距离衰减。对应到产品：

- hover/点击一个节点时，**邻域 1–2 跳高亮**，距离越远越淡；
- 检索命中时，不只高亮命中节点，也点亮它的邻居——这正是「联想」的可视化；
- 图上的边不是装饰，是扩散的通道（后面的算法要真的用它）。

### 2.3 系统巩固：为什么「删除会话才压缩一次」合理

记忆巩固理论里，海马体快速编码、皮层缓慢整合；重复提取会推动「系统巩固」。你的规则在工程上对应得很干净：

- **会话在 = 还在工作记忆里**：不压缩，保留原始细节（相当于海马体还握着它）；
- **会话删了 = 一次巩固**：压缩成摘要 + 抽取事实，进入长期存储（皮层）；
- **长期不用 = 降级为边缘记忆**：只留索引，等下一次提取再重建（再巩固）。

所以「删除才压缩」不是省事，而是把「巩固」绑定在一个明确的、用户可见的事件上——这比后台偷偷压缩更容易解释。

### 2.4 为什么三层而不是连续衰减

连续衰减在视觉上会变成一团糊；三层的价值是**离散、可解释、可操作**：

- 层 = 状态（活跃/游离/失真），状态决定「还能不能读原文」「检索要不要默认包含」；
- 层内半径 = 连续激活，表达「同样在游离层，谁更靠内」；
- 迁移有明确阈值与事件（删除、超时、被提及），可以写测试。

## 3. 视觉与交互：业界怎么画这类图

| 画法 | 代表 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- | --- |
| 力导向 | Obsidian 全局图、Gephi | 自动聚簇 | **每次打开位置都变**、节点多就抖、无法表达固定层级 | 探索未知结构 |
| 同心环带 | ego network 研究、径向图 | 层级/距离可解释、位置稳定、性能好 | 需要自己分配角度 | **以「我」为中心的记忆** |
| 分层树/DAG | 知识树、思维导图 | 关系明确 | 不适合多对多 | 单一来源层级 |

**选同心环带 + 局部微调**：你的模型本身就是「距离 = 亲疏」，环带最忠实；力导向「每次都不一样」会破坏用户的空间记忆（Obsidian 用户反复抱怨这点）。

四条直接借用的经验：
1. **本地图 / 全局图分开**（默认当前工作区+当前会话，点「全局」再展开）；
2. **颜色 ≤ 7 种**，一个维度一种颜色（层用半径、类型用颜色）；
3. **语义缩放**：远看结构、靠近才出事实点、再近才出文字；
4. **hover 高亮 1–2 跳邻域**，其余变暗（扩散激活的视觉版）。

明确不做：3D 球面、全量文字标签、自动重排动画、边穿过原点。

## 4. 形式化模型

### 4.1 节点

| kind | 说明 | 层 | 来源 |
| --- | --- | --- | --- |
| origin | Loopsoar 程序本身（唯一） | 中心 | 常量 |
| session | 会话 | L1 | sessionStore |
| fact | 事实/偏好/约定/教训 | L1（挂会话）或 L2/L3 | MemoryFact |
| tool | 工具（程序性记忆：这个工具怎么用、何时用） | L2 | 工具调用事件 + 工具注册表 |
| episode | 删除会话的压缩摘要 | L2 | contextCompress |
| entity | 实体（人/项目/文件） | 随所属节点 | tags/内容抽取（P2） |
| ghost | 失真记忆（摘要+关键词+指针） | L3 | episode/fact 降级 |

### 4.2 边

| kind | 从 → 到 | 语义 |
| --- | --- | --- |
| owns | origin → session / tool | 属于这个 agent |
| contains | session → fact | 记忆产生于该会话 |
| lineage | episode / ghost → session | 游离记忆的出身 |
| semantic | fact ↔ fact | 相似度 / 共享 tags |
| continuity | session ↔ session | 时间相邻或同主题 |
| usage | tool ↔ session / fact | 工具被该会话使用、产出了该事实 |
| recall | origin → node | 最近召回（瞬态动画，不入库） |

### 4.3 激活值：**工具调用选择也是一次使用**

~~~
使用事件 { at, w, kind }:
  kind=mention  用户在消息里提到        w = 1.0
  kind=tool     一次工具调用（选择即使用） w = 0.8   → 加在 tool 节点、所属 session、该调用产出的事实上
  kind=search   模型 memory_search 命中  w = 0.6
  kind=view     用户点开节点详情         w = 0.3

R = Σ_k w_k · exp(-(now - at_k) / τ)     τ = 30 天（可配）
B = ln(1 + R)
A = B / (B + 1)                           → (0,1)
A_final = A × (0.6 + 0.4 · importance/10)
~~~

**为什么把工具调用算进去**：Agent 的「习惯」主要从工具选择里长出来——同一个任务反复选同一个工具、绕过另一个工具，这就是程序性记忆。把 tool 做成节点、把每次调用记成一次 usage 事件，图上自然会出现「常用工具贴近中心、冷门工具沉到外圈」。

### 4.4 半径映射（距离 = 优先使用权重）

~~~
origin  r = 0
L1      r ∈ [ 90, 220]   session / 其事实
L2      r ∈ [260, 420]   tool / episode / 删除会话的事实
L3      r ∈ [460, 560]   ghost
~~~

层的边界是硬约束，层内半径连续：r = lerp(in, out, 1 - A_final)。

### 4.5 **检索排序以距离为第一权重**（本轮新增，覆盖原设计）

~~~
候选筛选：similarity ≥ θ_min（默认 0.05，只用来挡完全无关的）
排序：activation 降序（= 距离升序），similarity 只做并列打破
最终分 = 0.75 · activation_norm + 0.25 · similarity
~~~

这改变了我们现在 `effectiveValue × (0.3 + similarity) + tagBonus` 的结构——那套里相似度是主项，等于「越像越优先」；按你的规则应当是「越常用越优先，像不像只做门槛」。**这是我理解的核心差异，实现时会做成可配置（memoryRanking: 'distance' | 'similarity'），默认 distance。**

### 4.6 角度分配（稳定优先）

~~~
1. 会话基角 θ = hash(sessionId) 或按 createdAt 均分；
2. 会话子节点占扇区，宽度 ∝ 子节点数；
3. 子节点在扇区内按 activation 排序、等弧长分布；
4. 弧长 < 12px → 合并为聚合点「n」，点击展开；
5. 游离/失真节点角度继承来源会话 ± 固定偏移。
角度只在会话增删时变化，激活只改半径 → 空间记忆稳定。
~~~

### 4.7 视觉编码

| 通道 | 编码 | 规则 |
| --- | --- | --- |
| 半径位置 | 激活 + 层 | 见 4.4 |
| 大小 | 内容量/重要度 | 4–14px，log |
| 颜色 | 类型 | fact 灰蓝 / preference 青 / lesson 橙 / tool 绿 / episode 紫 / ghost 半透明 |
| 亮度 | 新近度 | 24h 100% / 7d 80% / 30d 55% / 更久 35% |
| 边宽 | 强度 | 1–3px；semantic 按相似度 |
| 虚线 | 失效/失真 | invalidated 与 ghost |
| 脉冲 | 召回/调用 | 600ms 光晕 + 边流光 |

## 5. 三层生命周期（状态机）

~~~
新建会话 ──▶ [L1 活跃] ──删除──▶ [压缩中] ──成功──▶ [L2 游离] ──超时 T2──▶ [L3 失真]
                │                    │                                     │
                │                    └─失败─▶ 保留原文                     │
                └──── 长期闲置 T1（事实降级）──────────────────────────────▶
                                                                           │
   [L3 失真] ──提及 / 搜索命中 / 点开────▶ [L2 游离]（rehydrate，只发生一次）
~~~

| 迁移 | 触发 | 动作 | 幂等 |
| --- | --- | --- | --- |
| L1 → L2 | `onSessionDeleting` 钩子（domains/chat.ts:321） | 读消息 → compressConversation → episode ≤400 字 + 抽高价值事实 + 标记来源已删 | episodeId = hash(sessionId)，只生成一次 |
| L2 → L3 | 每日任务：A_final < 0.15 且 > T2（90 天） | 二次压缩 ≤120 字 + 关键词，正文置空留指针 | 已是 ghost 跳过 |
| L3 → L2 | 提及/搜索命中/点开 | 按指针回取原文；失败则用 ghost 重建并标「不可恢复」 | 状态位只翻一次 |
| L1 事实 → L3 | 会话未删但 > T1（180 天）无使用 | 只降级事实，会话节点不动 | 按 fact 粒度 |

接入点都是现成的：`onSessionDeleting/onSessionDeleted`（index.ts:2403/2417）、`compressConversation`（core/src/contextCompress.ts:79）、`sessionStore.loadMessages()`。

## 6. 布局算法（确定性、零依赖）

~~~
layout(graph, viewport):
  for n: n.activation = activation(n.events); n.band = bandOf(n)
  sessions = sortBy(sessions, stableAngle)
  cursor = 0
  for s: s.sector = [cursor, cursor + 2π·leaves(s)/total]; cursor += width
  for s: s.r = lerp(L1.in, L1.out, 1 - s.activation); s.theta = mid(s.sector)
  for s, for i, c in sortBy(s.children, activation desc):
     c.theta = s.sector.start + (i+0.5)·width(s.sector)/len(children)
     c.r = s.r + childOffset(c.kind)
  for e in L2/L3:
     e.theta = angleOf(e.sourceSession) + jitter(e.id)·0.06
     e.r = lerp(band.in, band.out, 1 - e.activation)
  resolveCollisions(minArc = 12px)   # 分桶扫描，拥挤则合并聚合点
  project: x = r·cos θ, y = r·sin θ
~~~

复杂度 O(n log n)，2000 节点毫秒级；同一数据同一张图（只有激活变化引起半径微动，300ms 插值）。

## 7. 渲染方案（React + Canvas 2D，零新依赖）

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| DOM/SVG 一节点一元素 | 不采用 | 500 节点就开始掉帧；事件绑定额外开销 |
| 力导向库（d3-force / sigma） | 不采用 | 引入依赖 + 布局抖动；我们的布局是确定性的 |
| **Canvas 2D 自绘** | **采用** | 无依赖、可精确控制、2000 节点 60fps |
| WebGL（cosmos.gl） | 备选 | 上万节点才需要；先不引入 |

实现要点：

1. **两层画布**：静态层（边 + 环带）画一次缓存到 offscreen canvas，动态层只重绘节点与高亮；
2. **devicePixelRatio 适配**，坐标按 CSS 像素算、绘制时乘 dpr；
3. **命中测试**用网格哈希（cell 40px），hover/click 不做全量遍历；
4. **LOD**：缩放 z<0.6 只画 origin+session+tool；0.6–1.2 加 episode/fact；>1.2 加文字标签；
5. **动画**：rAF，半径插值 300ms、脉冲 600ms，动画结束即停（不常驻 rAF）；
6. **React 边界**：MemoryGraph 组件只收 props，内部 ref 管画布；节点数组不进 React state 高频更新。

性能预算：2000 节点 / 4000 边 → 首帧 < 50ms，交互帧 < 16ms；超过 5000 节点强制聚合。

## 8. 数据模型与接口

~~~ts
type MemoryNodeKind = "origin" | "session" | "fact" | "tool" | "episode" | "entity" | "ghost";

interface MemoryNode {
  id: string;
  kind: MemoryNodeKind;
  label: string;
  workspaceId: string;
  sessionId?: string;          // 来源会话
  factId?: string;             // 对应 MemoryFact
  importance: number;
  activation: number;          // 由事件算出，不入库
  band: "L1" | "L2" | "L3";
  createdAt: number;
  lastUsedAt: number;
  useCount: number;
}

interface MemoryEdge {
  id: string;
  kind: "owns" | "contains" | "lineage" | "semantic" | "continuity" | "usage";
  from: string;
  to: string;
  strength: number;            // 0..1
}

interface UsageEvent { at: number; w: number; kind: "mention" | "tool" | "search" | "view"; }
~~~

**存储策略（推荐）**：

- memory.json 继续做真相源，新增 events（每节点最多 50 条，超出按衰减合并）、episodes[]、ghosts[]；
- 图**不落盘**：主进程从 memory.json + sessionStore 派生快照，经 IPC 推给渲染层，结果缓存 1s；
- 迁移状态（band）与 ghost 标记落盘，避免每次重算；
- 事件写入走轻量路径（不触发 LLM、不做相似度扫描），单次 O(1)。

**IPC（新增）**：

~~~
memory:graph        → { nodes, edges, stats }            // 派生快照（按 workspace 过滤）
memory:graphEvent   → { type: 'recall'|'migrate', ids }  // 推送脉冲/迁移，驱动动画
~~~

| 全局/局部 | 开关切换；全局可按工作区着色、可「只看当前工作区」 |
| hover | 高亮 1–2 跳邻域 + 边流光，其余降到 30% 不透明度 |
| 点击 | 右侧 wiki 详情：正文、来源（会话/消息/URL）、反向链接、相关节点、编辑/删除 |
| 双击 | 以该节点为原点重排局部图（半径按与它的关联强度） |
| 滚轮 / 拖拽 | 语义缩放 / 平移 |
| 搜索 | 输入即高亮命中并自动缩放到命中节点 |
| 筛选 | 层、类型、时间范围、是否含失效 |
| 时间轴（M4） | 回放「这条记忆什么时候被用过」 |
| 键盘 | / 搜索、Esc 返回、+/- 缩放、F 聚焦 |

**召回反馈**：模型召回或工具调用时，主进程 push memory:graphEvent，渲染层让节点脉冲、流光从 origin 流向该节点 600ms。用户在聊天里看到「它刚想起这件事」，在图谱里能对上号——这是让记忆可解释的关键一环。

## 12. 验收与风险

**验收**：
1. 布局确定性（同一输入两次 layout 结果相同）；
2. 2000 节点 60fps（headless 基准 + 真机）；
3. 迁移幂等（重复删除不产生两个 episode）；
4. 工作区隔离（A 的图不出现 B 的节点）；
5. 距离优先排序（10 条同样相似但频次不同的记忆，断言高频在前）。

**风险**：图爆炸（节点上限+聚合+LOD 三道闸）；隐喻过度（图谱是第二视角，列表/搜索仍是主路径）；维护成本（新增节点 kind 需评审）；性能（Canvas 自绘约 600–900 行）；数据膨胀（事件上限 50/节点）。
