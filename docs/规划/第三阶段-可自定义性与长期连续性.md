# 第三阶段规划：可自定义性、长期连续性与可观测性

> 定稿：2026-11-16。输入：用户第三阶段指令、《框架灵活性审查》（`docs/FRAMEWORK-REVIEW.md` §四）、《代码审计与清理报告》（`docs/AUDIT-STAGE3-PREP.md`）、第二阶段收口记录（ADR-0100~0107）。
> 前置：第二阶段（Agent ↔ 浏览器打通）已收口；本阶段开工前已完成一轮死代码清理与 P0 修复（见审计报告 §3/§4）。
> 总原则：**安全、稳定 > 自由度**；单源纪律不变；每个切片独立可验收、可回退。

---

## 一、阶段目标（四条主线）

1. **可自定义性补齐**——把「万物皆插件」从「只有 tools」推进到「权限可信 + 多贡献点可装载」，让用户能在不改内核的前提下换 loop、换主题、换 Agent 预设、换地址栏命令。
2. **长期连续性**——记忆按工作区隔离（ADR-0094 遗留），会话/任务/工作区三层关系落到检索与写入，Agent 记得「这个项目怎么做过」。
3. **可观测与可接管**——Agent 每一步动作可回放（trace），浏览器观测面从「整页快照」升级为「局部检索 + 控制台/网络 + 条件等待」，人能看懂也能接手。
4. **工程硬化**——超大文件收口、契约瘦身（死通道/死事件/重复定义）、E2E 钩子出主进程、core 打包出口可被 Node 真实加载。

> 明确**不做**（本阶段）：多 Agent 并行编排、群聊、屏幕控制（UIA）、Android 端、Cloudflare 云同步（见 `docs/规划/0.1.0后-Cloudflare-GitHub-产品化与同步.md`，0.1.0 发布后再启动）。

## 三、全程红线（不可破）

1. **三道安全闸不许合并**：会话授权（开关）／策略档（权限）／敏感步骤（逐次确认）。任何「为了流畅绕过敏感确认」的改动都是回归。
2. **可见面 = 执行闸**：任何工具过滤必须同时作用于 `registry.toolSchemas()` 与执行器。
3. **单源纪律**：新契约一律 contracts → `pnpm gen`；实现者不得手改 `gen/`、`dist/`。新增通道必须同步 preload 白名单与守卫。
4. **fail-closed**：新开关默认关；超时/取消 = 不执行；校验失败 = 拒绝装载而不是降级放行。
5. **不改内核四件语义**：壳、引擎、安全护栏、插件宿主；扩展只能经注册表获取能力，不得直接碰 electron / fs。
6. **每片独立可回退**：一片一提交，提交信息沿用现有风格；回退条件写进 ADR。

## 四、验证与提交纪律

- 每片验收：`pnpm -r typecheck` + 定向 spec 绿 + 全量 `npx vitest run`。
- 阶段末：`pnpm gen && pnpm check` 逐字节一致、`pnpm build` 全绿、真机 E2E（`LOOPSOAR_E2E_*`，证据进 `e2e-evidence/`）。

- 文档：每片追加 ADR 条目；`docs/PROGRESS.md` 滚动更新；`docs/FRAMEWORK-REVIEW.md` 在本阶段结束时重写为现状版。
