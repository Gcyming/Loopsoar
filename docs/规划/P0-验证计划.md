# P0 验证计划（Loopsoar）

> 定位：开工前**必须完成的验证**，不是开发任务。五条工作线并行，时间盒 **2–3 周**；每条线有明确绿灯标准与红灯处置。P0 的产出直接决定 ADR-0002/0003/0007 的裁决。
> 总出口：五条线全绿 → 冻结 `BrowserAdapter` 接口、确定基座主线、确定记忆后端 → 进入 P1。

---

## W1 浏览器原型（D0 决策门，优先级最高）

**目标**：在冻结浏览器适配器接口与基座主线之前，验证「WebContentsView 主实现」能否支撑完整浏览器 + 浏览器自动化。

### 1.1 最小原型范围

- Electron 当前稳定版（45 起）最小应用：一个主窗口 + 一个 WebContentsView 实例；
- 实现 BrowserAdapter 草稿接口的最小子集：navigate / snapshot / click / type / scroll / screenshot / wait / JS 注入。

### 1.2 验证项与通过标准

| # | 验证项 | 通过标准 |
|---|---|---|
| ① | 核心操作 | 第三方网页（≥3 个真实站点，含登录页）导航、截图、元素定位与点击、JS 注入全链路可用 |
| ② | 会话与窗口 | 多标签（多 WebContentsView 实例）、Cookie 分区（`persist:` 语义）、登录状态保持、`window.open`/`target=_blank` 弹窗策略、权限弹窗处理——逐条对照 slime 13 个 browser 工具需求，**无不可替代项** |
| ③ | 存量评估 | 13 个 browser 工具逐条给出「复用 / 改实现不动语义 / 重写」清单 + 工作量估计 |
| ④ | 浏览器功能面可行性 | 多标签栏、地址与搜索一体框、书签、历史、下载、广告拦截（请求拦截等价物 `webRequest`）、页面全文保存、独立任务标签组——在 WebContentsView 体系下逐项给出实现方案（含已知缺口） |
| ⑤ | 对抗初探 | 网页内容能否借助预加载桥/`window.open` 触达主进程能力——至少跑通发布门 2 的 4 条攻击路径中的 2 条并记录结果（完整用例在 P6 前补齐） |

### 1.3 红灯处置

- ①/② 任一未达标 → **冻结基座决策**（ADR-0002/0003 维持待验证）：扩大原型范围或引入 CDP 兜底重试；仍不达标 → 重开基座评审（新 ADR）。
- ③ 未完成 → 不写 browser 工具正式实现。
- ④ 发现不可替代缺口 → 该功能移出 MVP 必须清单并登记 ADR。

## W2 契约生成管线

**目标**：证明「单一 schema → 类型/校验器/IPC 常量/preload 白名单」可落地，且死码在 CI 变红。

### 2.1 范围

1. `contracts/` 定义最小 schema：IPC 通道（10 个以内，覆盖 chat/perm/file 三域）+ 消息类型；
2. 生成器产出：TS 类型 + zod 校验器 + `IPC_CHANNELS` 常量 + preload 白名单声明；
3. 启动期断言：**声明的通道必有 handler、注册的 handler 必在声明内**；
4. 守卫测试：在 CI 中故意删一个 handler → 变红；补回 → 变绿（可红可绿是验收项本身）。

### 2.2 通过标准

- 生成的类型在 `tsc --noEmit` 下通过；校验器对非法参数返回结构化错误；
- 断言测试可红可绿；契约变更必须经过生成器（手改生成物 → CI 红）；
- 敏感 handler 四要素（调用方身份/帧来源/参数合法性/权限上下文）至少在一个通道上完成可测实现。

## W3 最小工具轮（无壳 harness）

**目标**：证明迁移后的引擎骨架在**无 GUI、无 Electron** 的环境能跑通一次完整工具轮（对应 ADR-0006 第一批 + ADR-0004 platform=node）。

### 3.1 范围

1. 从 slime 迁移最小集：router（单提供方降级链）、tool_loop 核心、claims、filter、session 常量段（stable/volatile 分离）；
2. 工具：`file_read` 一个（走 platform 适配层 fs 实现）；
3. 权限：grant → policy → 执行 → 结果回灌 → done 事件；
4. 验证点：四闸可触发（轮次置小）、心跳事件、`[错误]` 前缀失败语义、声称核验触发。

### 3.2 通过标准

- 无壳 harness（`node` 直接跑）完成：模型调用 → 工具执行 → 回灌 → 终答；
- 五问清单随迁模块提交（依赖/接口/测试/缺陷/验收五表齐全）；
- 迁移过来的 slime 测试在本仓 CI 实际变绿（不绿不计入）。

## W4 安全拒绝路径（攻击性用例先行）

**目标**：安全发布门 1、2、3 的反例集先落地（ADR-0009），证明「预期拒绝」可自动化验证。

### 4.1 反例集（每条 = 攻击输入 + 预期拒绝 + 自动化用例）

| 域 | 反例 | 预期结果 |
|---|---|---|
| 权限 fail-closed | 未注册工具名；目标越出工作目录（未授权）；L5 系统操作；工具表为空时判「不存在」不判「拒绝」 | 拒绝（或按「判不了≠不存在」语义放行装配判断），行为有断言 |
| 危险命令 | `rm -rf /`、`dd`、`mkfs`、`curl \| bash`、`chmod -R`、fork bomb、全局包安装 | hard_rules 正则阻断 + 可读原因 |
| IPC 冒用 | 伪造 sender 帧调用敏感通道；非 `loopsoar://` 来源 | 统一受信入口拒绝（四要素缺一即拒） |
| 浏览器桥逃逸 | 预加载脚本注入、`window.open` 逃逸、CDP 端口滥用（W1-⑤ 先行 2 条） | 网页拿不到主进程能力 |
| SSRF | 13 段私网地址、IP 直连、重定向链 >5、**DNS 解析结果 ≠ 重定向目标 ≠ 实际连接目标**（rebinding 类） | 全部拒绝；三跳一致性有断言 |

### 4.2 通过标准

- 每条反例有自动化用例且进 CI 常跑；
- 安全发布门 1、3 在 P2 结束时全绿、门 2 在 P6 结束时全绿（此处先行 2 条攻击路径）。

## W5 记忆负载测试（裁决 ADR-0007）

**目标**：用真实/脱敏语料实测 sqlite-vec 与 LanceDB，把「性能阈值 + 测试硬件」写进验收。

### 5.1 测试设计

- **语料**：真实或脱敏的记忆语料 **10 万条**（含中文，覆盖 fact/preference/lesson 等类目；不用合成模板）；
- **对照**：sqlite-vec（BGE-M3 向量 + BM25 混合，沿 slime 五闸阈值 0.75/0.70/0.68）vs LanceDB 基线；
- **指标**：检索质量（召回/命中，评测集打分）、P50/P95 延迟、磁盘体积、增量写入速率、备份恢复时间、归档查回正确性；
- **硬件（写入验收）**：i9-13900HX / RTX 4070 Laptop 8GB（用户实机；结果同时记录 CPU-only 一项）。

### 5.2 通过标准（初定阈值，实测校准后固化为验收）

- 检索 P95 ≤ 50ms @ 10 万条（参考硬件）；
- 检索质量不劣于 LanceDB 基线；
- 备份恢复与归档查回 100% 正确；增量写入无死锁（并发写场景）；
- 输出报告 → 附入 ADR-0007，裁决默认后端。

### 5.3 红灯处置

- 质量/延迟不达标 → 维持 LanceDB 默认（ADR-0007 回退路径）。

## 总出口判定

| 线 | 绿灯 → | 红灯 → |
|---|---|---|
| W1 | 冻结 BrowserAdapter 接口；基座主线锁定（ADR-0002/0003 → 已验证） | 冻结基座决策，重开评审 |
| W2 | 契约管线进入 CI；IPC 安全入口有可测语义 | 收缩 schema 范围重试 |
| W3 | 引擎迁移第一批放行（P1 开工） | 该模块登记重写方案 |
| W4 | 安全反例进 CI；发布门 1、3 雏形就位 | 追加用例，不降标准 |
| W5 | 记忆后端裁决（ADR-0007） | 走回退路径 |

**时间盒**：2–3 周。超时未全绿 → 逐线评估是「缩小范围」还是「延期开工」，写进 ADR，不静默带病开工。
