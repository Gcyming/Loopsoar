# 服务端待办

> 只记录**必须有服务端**才能做的能力：账号、支付、中心化审核、实时推送、云端执行、企业管控。
> 能靠静态托管 / 客户端完成的（如目录签名、撤销列表、灰度通道）不放进这里。

## 待办

| 优先级 | 事项 | 为什么需要服务端 | 验收标准 | 状态 |
|---|---|---|---|---|
| P1 | 自动更新轮询 / 推送 | 客户端只能定时拉静态目录；真正“发布即生效”需要服务端下发版本与通道信息 | 发布新版本后，在线客户端在约定时间内提示更新；可按通道灰度 | 未开始 |
| P1 | 中心化发布审核 | 静态目录无法阻止任何人上传 zip；需要服务端做账号、扫描、人工审核、下架 | 未审核包无法进入正式目录；审核记录可追溯 | 未开始 |
| P1 | 实时远程停用 | 静态撤销列表要等客户端下次拉目录；紧急止损需要推送通道 | 标记恶意扩展后，在线客户端在秒级停止运行 | 未开始 |
| P2 | 账号体系与设备授权 | 需要服务端保存用户、设备、许可证与登录态 | 登录/登出/设备上限/许可证校验可用 | 未开始 |
| P2 | 评分、评论、下载统计 | 需要持久化、聚合与反作弊 | 扩展详情页展示真实评分/评论/下载量 | 未开始 |
| P2 | 支付 / 订阅 / 许可证 | 需要订单、支付回调、发票与权限同步 | 购买后解锁付费扩展；退款/到期可回收 | 未开始 |
| P3 | 企业 SSO / 审计日志 | 需要组织、角色、IdP 对接与集中日志 | 企业可配置 SSO；管理员可导出审计事件 | 未开始 |
| P3 | 云端执行 / 托管 Agent | 客户端算力与在线时长不可控 | 任务可提交到云端执行并回传结果 | 未开始 |

## 记录规则

- 新增项直接加一行，写清「为什么静态方案做不到」。
- 能通过 GitHub Pages / Releases / 对象存储解决的，不记在这里。
- 状态用：未开始 / 进行中 / 已完成 / 已放弃。
