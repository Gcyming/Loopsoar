# ADR-0013 会话流按会话隔离 + 会话 UI 纯模块化

- **背景**：2026-11-01 用户实测：流式生成中切换会话再切回，出现「看起来已结束但仍在跑」「停止后报错」「显示模型与所选不一致」；同时会话回复 UI 与 slime 仍有差距（正文/思考吐出顺序、正文分隔、光标、锁定最新）。根因不是单点 bug：
  1. UI 只有一个全局「当前助手消息」指针与全局 `messages`，流事件不区分会话；
  2. shell 的 `chat:stop` 手工补发了一次 `done`，与服务自身收尾的 `done` 重复；
  3. 原生 WebContentsView 的 bounds 未让出侧栏拖拽条，打开网页后分隔条被视图覆盖；
  4. 会话观感逻辑散落在组件里，无法复用 slime 已验证的滚动/吐字结论。
- **决策**：
  1. **流事件必须按 `sessionId` 路由**：UI 维护 `Map<sessionId, ChatMessage[]>` 消息缓存与 `Map<sessionId, SessionStreamMeta>`（activeId / startedAt / firstTokenAt / busy / stopping）；`chat:stream:*` 只写事件所属会话，当前可见会话才同步到 React state。切走 = 后台继续写自己的缓存，切回 = 恢复缓存并恢复 busy/停止按钮；新建会话不继承任何流状态。
  2. **每个会话只有一个收尾来源**：服务 emit 的 `done`/`error` 是唯一权威；shell 不得手工补 `done`。用户主动停止的 abort 由 UI 的 `stopping` 标记收束为「已停止」+ 中断原因，不显示红色失败。
  3. **会话 UI 的认知逻辑抽成纯模块**：
     - `scrollFollow.ts`：锁定最新判据（滚轮解锁、8/48px 滞回、内层滚动豁免），DOM 循环留在 MessageList；
     - `streamFadeSplit.ts`：吐字切分（settled 止于换行、尾行渐入、未闭合代码回退）；
     - `chatStreamState.ts`：事件→消息状态的唯一转换 + 会话流元信息类型/工厂。
  4. **布局常量单一来源**：`LAYOUT.SPLITTER_WIDTH` 与 `computeBrowserViewBounds` 同源，原生视图必须让出分隔条；新增 UI 可点击区域时，先检查是否被 WebContentsView 覆盖。
- **理由**：会话切换是高频操作，状态一旦串台会同时破坏「输出完整性、停止语义、模型归属」三件事；把会话当作一级状态边界（而不是切换时清空）是唯一能同时修好三者的结构。纯模块化让 slime 的经验可测试、可替换，而不是继续堆进 App。
- **替代方案**：
  - 切换会话时强制停止旧流——被否（丢失后台输出，且用户明确要求继续使用 slime 的体验）；
  - 每次切换重新拉历史并丢弃实时缓存——被否（切回后内容缺失/假完成，正是本次 bug）；
  - 继续用全局 activeAssistantRef + 事件补丁——被否（无法表达并发会话，后续多 Agent/后台任务会再次爆）。
- **验证方式**：`tests/ui/scrollFollow.spec.ts`、`tests/ui/streamFadeSplit.spec.ts`、`tests/ui/chatStreamState.spec.ts`（含会话元信息默认值）；E2E `session-switch` 模式（长流中切新会话再切回，证据 `docs/screenshots/gui-84-session-switch.png`）与停止（`gui-85-stop-ok.png`）；布局测试锁定分隔条让位宽度。
- **状态**：✅ 已验证（单测 + E2E；会话切换与停止路径）
- **回退条件**：若后续引入多窗口/多进程渲染，UI 会话缓存需下沉到独立 store（新 ADR），但「按 sessionId 路由 + 单一收尾源」不变。
- **复核时间**：下一次会话/后台任务相关功能开工前
