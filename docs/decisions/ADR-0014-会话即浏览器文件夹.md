# ADR-0014 会话 = 浏览器"文件夹"（网页与标签按会话隔离）

- **背景**：2026-11-01 用户明确规定：单个会话是一个"文件夹"，该会话新建的网页等一切页面只出现在当前会话。左侧网页与右侧会话高度绑定；点击会话记录后，左侧切换为该会话打开的内容。工作会话里的 Agent 只能操作自己会话的浏览器，不能串到别的会话正在看的页面。用户同时要求：查证能否用 Cloudflare（免费、无服务器）关联 GitHub 做跨设备持久化；本轮只查证，不实现云端同步。
- **决策**：
  1. **浏览器宿主按 `sessionId` 分组**：`BrowserHost` 维护 `Map<sessionId, SessionGroup>`（标签集合 + 活动标签）；只有当前会话的活动标签可见，其它会话的页面保留在内存但隐藏。切会话只换可见组，不销毁页面。
  2. **Agent 工具必须按会话上下文操作**：`ToolContext.sessionId` 贯穿到 `browser_*` 工具，所有 `BrowserHost` 读写方法接受可选 `sessionId`；后台会话的 Agent 在隐藏的自家标签里操作，不影响用户当前所见会话。
  3. **本地会话持久化**：`SessionStore` 的会话文件增加 `browser: { tabs, activeIndex }`（URL/标题/历史栈，不存页面内容）；标签导航/新建/关闭/切换时防抖落盘，退出前全量落盘。重启后恢复最近会话（左右一起恢复）；切回其它会话时按该会话快照恢复或展示其内存中的活页面。
  4. **UI 单一可见事实**：`browser:tabs` 事件只推送当前会话语义；UI 切会话时同步刷新标签与地址栏；切到空会话必须清空地址栏/当前页面，不残留上一个会话的 URL。
  5. **云端持久化只做调研**：结论见 `docs/research/session-browser-persistence-cloudflare.md`；推荐 Cloudflare Workers + D1 + GitHub OAuth Device Flow + 客户端加密，不做 GitHub 仓库当数据库。未获用户批准前不接入网络/账号体系。
- **理由**：会话是用户的"工作空间"，浏览器状态是最能体现工作空间边界的数据；把浏览器状态挂在全局会直接违反用户要求，也会让后台 Agent 操作错页面。分组 + sessionId 路由是能同时满足"切回看到原页面"和"Agent 不越界"的最小结构；本地持久化先解决"关掉再开"的刚需，云端只是备份/跨设备，不能成为主链路依赖。
- **替代方案**：
  - 每个会话一个独立 BrowserWindow/进程——被否（Electron 内存成本高，窗口管理复杂，当前不需要真隔离）；
  - 切会话时销毁旧页面、切回重新加载——被否（丢登录态/滚动位置，且用户要求"显示退出前打开的界面"）；
  - Agent 工具只操作当前可见会话——被否（违反"对应会话 Agent 只能操作对应浏览器"，后台任务会串台）；
  - 把页面状态写进聊天消息——被否（污染对话数据、体积大、恢复语义不清）。
- **验证方式**：`tests/shell/browserSessionHost.spec.ts`（会话标签隔离/工具按 sessionId/快照恢复/删除会话）、`tests/shell/browserSessionState.spec.ts`（持久化净化）、现有 `browserHost.spec.ts` 回归；E2E `session-tabs`（A 开页→新建 B→切回 A，gui-87）与重启恢复（gui-88）；全量单测/typecheck/gen/check/build。
- **状态**：✅ 已验证（本地会话隔离 + 重启恢复）；🟡 云端持久化待用户批准后做（POC 方案见研究文档）
- **回退条件**：若后续多窗口/多进程渲染成为主形态，分组下移到独立 store；"按 sessionId 路由 + 工具不得跨会话"不变。
- **复核时间**：云端同步功能立项前 / 多窗口改造前
