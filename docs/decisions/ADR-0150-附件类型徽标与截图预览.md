# ADR-0150 附件类型徽标与截图预览

日期：2026-11-28
状态：已采纳

## 背景

1. v0.0.2 反馈：拖入 Word/Excel/PPT/PDF/Markdown 等办公文档后，输入框只有通用文件图标，用户难以一眼分辨类型；Windows 文件选择框本身接受全部类型，但界面没有把「类型」表达出来。
2. 浏览器操作期间，用户看不到 agent 截下的页面截图；agent 侧此前只要模型能力表未标注 vision 就不回灌图片，自定义供应商的视觉模型也永远收不到截图。

## 决策

- 输入框附件 chip：图片继续显示缩略图；非图片附件显示 3~4 字符的类型徽标（DOCX/XLSX/PPTX/PDF/MD…）+ 文件名，不再显示路径文本。文件选择框保持不设 filters，任何类型都可作为附件。
- 截图回灌：browser_screenshot 仅在 visionEnabled() === false（明确 text-only 或设置里关闭图片输入）时只返回路径；能力表未填（undefined）按支持处理，交给上游裁决。单图上限从 1.5MB 放宽到 3MB（1900x1200 PNG 常见 1.5~2.5MB）。
- 截图给用户看：tool 事件不携带 base64（避免 MB 级 IPC），只从结果文本解析 .loopsoar/screenshots/*.png 路径；UI 时间线的工具卡用 fs.readImage 懒加载预览，点击放大/还原。图片不存在时回退为文件名提示。

## 后果

- 办公文档与图片在输入框、消息气泡中都以附件 chip 呈现，路径只作为 title 提示。
- 视觉模型（包括能力表未填的自定义模型）能直接看到截图；明确 text-only 的模型仍只能拿到路径，可改用 browser_snapshot 的 DOM 文本。
- 截图预览按需读取，不增加流事件的 IPC 载荷；历史消息不持久化时间线图片。
