# ADR-0144：扩展 / 技能 / MCP 三体隔离

状态：已采纳（实现于 `packages/core/{extension,skill,mcp}.ts` 与对应 shell 域）

## 背景
「万物皆插件」容易把三种完全不同的东西混成一锅：可执行插件、提示词知识、外部工具协议。
混在一起会导致权限模型与故障面失控。因此明确三者是**独立子系统**。

| 维度 | 扩展（Extensions） | 技能（Skills） | MCP |
|---|---|---|---|
| 本质 | 本地可执行插件（清单 + 入口） | SKILL.md 纯文本知识/流程 | 外部进程/服务的标准工具协议 |
| 存放 | `<dataDir>/extensions/<id>/loopsoar.extension.json` | `<dataDir>/skills/<id>/SKILL.md` | `<dataDir>/mcp.json` |
| 状态 | `<dataDir>/extensions.json` | `<dataDir>/skills.json` | 同配置文件 |
| 通道前缀 | `extensions:*` | `skills:*` | `mcp:*` |
| 能力边界 | 后续由插件宿主注册工具/命令 | **只注入提示词，不提供工具** | 工具以 `mcp__<server>__<tool>` 注册进 ToolRegistry |
| 权限 | 清单声明 + 沙箱/确认 | 无（不产生任何工具调用） | 声明 `network`，仍走沙箱与确认 |
| UI 分区 | 扩展 | 技能 | MCP |

## 决策
1. 三者目录、状态文件、IPC 通道、设置分区、测试文件全部独立，不共享存储与生命周期。
2. 唯一合法的集成点：
   - 技能 → `ChatService.getSkillPrompt()`（volatile 段注入）；
   - MCP → `ToolRegistry`（注册工具，复用既有执行/权限/审计链路）；
   - 扩展 → 后续插件宿主（同样只允许注册工具/命令）。
3. 任一子系统故障不得影响其它两个：扫描/连接失败只报错并降级，不阻断应用启动或对话。

## 影响
- 新增能力时先判断落哪个子系统，不允许"顺手复用"另一边的存储或通道。
- 守卫测试（channels-have-handlers、ui-contract、project-isolation）继续兜底。
