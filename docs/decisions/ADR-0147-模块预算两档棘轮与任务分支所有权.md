# ADR-0147 模块预算：两档 + 棘轮（行数红线第二代），以及任务分支的所有权

- 日期：2026-11-20
- 状态：✅ 已验证（typecheck 5/5、282 文件 / 2117 用例、build、E2E 真机跑通含 fork 路径；P2 `forkMatch` 已硬断言）
- 关联：ADR-0146（App <1200 目标）、`tests/guards/source-size.spec.ts`、`tests/guards/fault-injection.spec.ts`

## 背景

第一代行数红线写的是「所有源码文件 ≤ 1500 行」。上线后并没有出现预期的拆分，而是出现了**贴线行为**：
四个核心文件长期停在 1435–1494 之间（`browserTools.ts:1495`、`browserHost.ts:1498`、`App.tsx:1468`、`memoryService.ts:1449`），
每次加功能都在 10 行余量里挤。

根因不是「开发者不自觉」，是**守卫设计错误**：一条只写上限的规则，等于宣布「不变是合规的」。
而架构债务的本性是只增不减——只要允许不变，就没有人会主动变小。红线于是从「约束」变成了「目标」。

第二个问题同源：`index.ts` 的启动闭包里有四份与「浏览器任务分支」有关的状态
（待分支集合、分支点、落盘记录、回合起始快照），被三个入口读写，恢复逻辑与转发逻辑相隔 300 行。
它不违反任何一条现有守卫，但每次改都要靠记忆维持一致性——这类「无主状态」是长文件之外更隐蔽的债务。

## 决策

### 1. 两档预算

- **默认档 `MODULE_MAX = 1400`**：任何未登记的源码文件不得超过。比第一代收紧 100 行，留出余量但不允许贴线。
- **组合根档 `COMPOSITION_ROOTS`**：Electron 主进程入口、UI 根组件、记忆门面这类「装配/编排」文件，
  登记后可超过默认档，但必须同时写明 `reason`（为什么大）与 `target`（下一步怎么拆）。
  登记条目在评审里可见，因此这份清单天然只减不增。

当前登记三条：`index.ts:1413`、`memoryService.ts:1449`、`App.tsx:1468`。
（`refs.ts:1400`、`Settings.tsx:1381` 已在默认档内，无需登记。）

### 2. 棘轮（本 ADR 的核心）

白色清单里的 `ceiling` **等于当前实际行数**，且：

- 文件变大 → 失败；
- 文件变小 → **也失败**，提示把 `ceiling` 下调到新的实际值。

第二条是关键：没有它，「这次顺手减了 80 行」的成果会被下一次改动吃掉（天花板还停在旧值，余量重新出现）。
有了它，每个组合根的唯一合法状态是「和上次一样大，或更小」。

等价的可执行表述：**在这份清单里，你无法通过任何一次提交让文件净增长。**
要加代码，先移出等量代码——这把「要不要拆」从品味问题变成了编译期问题。

### 3. 任务分支状态机独立成类

`packages/shell/src/main/taskForks.ts` 的 `TaskForkCoordinator` 独占四份状态，提供四个入口：

| 入口 | 时机 | 责任 |
| --- | --- | --- |
| `onTurnStarted` | 回合开始 | 记分支点（本轮之前的消息数） |
| `markBrowserAction` | Agent 首次动手 | 会话临时标为任务（折叠区立即出现），落盘待分支记录 |
| `settle` | 回合结束 | fork + 搬本轮消息 + 过户任务身份 + 搬标签存档 + 推 `chat:taskForked` |
| `recover` | 启动 | 补完崩溃前未 fork 的记录，清掉孤儿标记（幂等） |

不变量（并发/崩溃都成立）：

1. 任何时刻「任务身份」只属于一个会话（原会话或分支，不同时）；
2. 分支点 ≤ 本轮开始前的消息数（操作过程不会复制两份）；
3. 落盘记录与内存状态同源，每次变更先改内存再整体落盘（可重放）；
4. 没有可搬内容的孤儿记录在恢复时被清掉，不留「任务但没有分支」。

`index.ts` 只保留装配：`onTurnStarted` / `onTaskCreated` / `onTurnSettled` 各一行委托。

## 后果

- 正向：新增文件无法再贴线；组合根只能变小；分支状态有了明确所有者与 7 条直接单测（此前只有 E2E 覆盖）。
- 代价：给组合根加一行也要先移出一行。这是有意的摩擦——它把决策提前到了写代码之前。
- 未完成：`App.tsx:1468` 仍高于 ADR-0146 定下的 1200 目标，下一步按 `COMPOSITION_ROOTS` 里的 `target`
  把 body JSX 抽成 `AppBody`（约 -400 行），届时必须同步把 `ceiling` 下调。
