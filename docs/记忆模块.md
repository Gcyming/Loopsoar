# 记忆模块（Loopsoar）

> 目标：让 Loopsoar 在长期使用中「记得住、找得到、改得动、可审计」，并且数据不被工具锁死。
> 本文是模块的运维与设计总览；具体决策记录见 docs/decisions/ADR.md（ADR-0110 ~ 0127）。

## 1. 数据布局

```
<dataDir>/memory/
├── vault/                     ← 真相：Obsidian 可直接「打开文件夹作为仓库」
│   ├── facts/<date>-<slug>.md 一条记忆一个文件
│   ├── archive/<id>.md        归档条目
│   ├── index.md               自动生成的目录（wikilink）
│   └── .loopsoar/index/       内容哈希索引（可丢弃缓存，32 分片）
├── usage.json                 遥测：accessCount / lastAccessed / confidence / usage 事件（可丢弃）
└── memory.json.migrated       旧 JSON 库的迁移备份（一次性）
```

**原则**：Markdown 是唯一真相；`usage.json` 和 `.loopsoar/index` 都是派生缓存，删掉只会变慢，不会丢数据。

## 2. 一条记忆长什么样

```markdown
---
schema: 1
id: m1                     # 稳定锚点：链接 [[m1]] 靠它（文件名可以变）
aliases: [m1]
title: "pnpm 依赖约定"      # 可选：回顾命名/人工标题，缺省用正文首段
category: convention
workspace: default
importance: 9
created: "2026-11-16T07:11:45.240Z"
tags: [design]
links: ["[[m2]]", "[[m3]]"]
invalidated_at: null       # 失效时间（被取代/被合并）
superseded_by: null        # 指向取代它的条目
provenance:
  trust: user              # user / agent / tool / web
  session: s-graph
  captured_by: auto
  
记忆正文。
```

命名规则：首次落盘 `YYYY-MM-DD-<正文前 24 字>.md`；之后内容更新不改名（外部链接稳定）；同名追加 id 后缀；Windows 保留设备名加 `_` 前缀。

## 3. 写入路径

1. 五闸过滤：容量 / 去重 / 取代 / 跨 agent / 工作区隔离；
2. 顺序：取代 → 去重 → 合并 → 新增 → 建链 → 容量（刻意把取代放在去重之前，否则「改为 X」会被当成重复）；
3. 落盘：单文件 tmp → fsync → rename；内容没变不重写；
4. 索引：只重写 `shardOf(id)` 一个分片；
5. 遥测：只写 `usage.json`，不因召回改 md。

## 4. 读取路径

- **自动注入**：召回门控（上次/这个/引号/路径/专有名词…）命中才检索；按会话工作区隔离；条数上限 6；
- **显式检索**：memory_search 工具，混合检索（hash 向量 + 词法），不经过门控；
- **富者愈富防护**：自动注入不增加 accessCount，只有显式检索才 touch。

## 5. 索引与一致性

- 索引条目：`{path, hash(sha1), fact}`，按 id 分 32 片；
- 启动：读索引 → **直接服务**（10k 约 60–260ms）→ 后台逐文件哈希核对；
- 核对：哈希一致复用解析结果；不一致才解析；文件删除则移除；只有变化的 fact 更新向量；
- 运行期：`fs.watch(vault, recursive)` 400ms 防抖同步外部编辑；自己写入的哈希一致，不会自激；
- 失败模式：索引损坏/缺失 → 全量解析；监听不可用 → 重启生效；单文件解析失败 → 跳过并告警，不写回。

## 6. 回顾（LLM）

- 候选：最多 24 条（重要度 → 最近使用）；
- 输出：`{titles, merges}`，严格校验（id 存在、每组 2–3 条、跨组不重复、标题/理由长度）；
- 应用：**必须确认**；titles 只改 frontmatter `title`；merges 保留一条，其余标记 `invalidated_at + superseded_by + status=merged:<分类>`，**文件不删除**，可手工恢复；
- 无模型/超时/非法输出 → 保留原规则标题，不影响其它功能。

## 7. 图谱与回放

- 设置 · 记忆：2D/3D 图谱（Canvas），节点按激活值布局，点击看详情；
- 时间回放：滑块回放到任意时刻，只显示当时已存在的条目；当时已失效的画空心环；
- 导出：Markdown 单文件快照（只读投影）。

## 8. 运维

| 操作 | 做法 |
|---|---|
| 备份 | 复制整个 `memory/vault` 目录（或 git init 后提交） |
| 迁移 | 换机器复制 vault；`.loopsoar` 与 usage.json 可不带 |
| 人工编辑 | 直接用 Obsidian/任意编辑器改 md，运行中 400ms 内同步 |
| 恢复被合并条目 | 把 `invalidated_at`/`status` 改回 active，保存即可 |
| 重建索引 | 删除 `.loopsoar/index`，下次启动自动全量重建 |
| 清空 | 设置 · 记忆 · 清空（同时清 md 与遥测） |
| 旧 JSON | 首次加载自动迁移并改名 `.migrated` |

## 9. 性能（同机合成数据）

| 数据量 | 冷启动（无索引） | 热启动（索引） | 后台核对 |
|---|---|---|---|
| 2,000 | 329ms | 58ms | 148ms |
| 10,000 | 1,533ms | 257ms | 760ms |

写入：单条记忆只改一个 md + 一个分片 + usage.json；召回只改 usage.json。

## 10. 已知限制 / 下一步

- 后台核对期间（10k 约 0.7s）召回可能读到旧值，设置页会显示「索引核对中」；
- 哈希与解析仍在主线程（下一步 worker）；
- 合并只做信息并集，不改写正文；
- 回顾一次 24 条，未做后台批处理；
- 真实语料评测尚未接入（当前 60 题合成用例）。
