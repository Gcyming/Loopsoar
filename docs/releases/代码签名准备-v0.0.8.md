# Windows 代码签名准备（v0.0.8 前）

> 结论先行：**代码签名不是应用里的设置项，而是构建阶段用受信任证书对 exe 做的 Authenticode 签名。**
> 0.0.2–0.0.7 都是内测，暂时不签名；计划从 **v0.0.8** 开始准备证书和签名链路，避免过早把发版节奏卡在采购/验证上。

本项目当前版本：`0.0.2`；发布门禁见 `docs/发布阶段.md` §6.1。
打包入口：`pnpm package:win` → `scripts/package.mjs` → `electron-builder@26.18.0`。

---

## 1. 签名发生在哪里

```text
证书/云签名账号（CA 或 Azure）
        │
        ▼
Windows 构建机 / CI（私钥在令牌/HSM，或 PFX，或云端）
        │  electron-builder 调用 signtool / Azure 模块
        ▼
Loopsoar.exe  →  NSIS 安装器 / 卸载器  →  release\dist\Loopsoar-Setup-<version>.exe
        │
        ▼
SHA256SUMS.txt（必须在签名完成后再生成）
```

- 配置位置：`electron-builder.yml` 的 `win.signtoolOptions` 或 `win.azureSignOptions`。
- 凭据位置：环境变量或 CI Secret；**绝不进仓库**。
- 不需要、也不能在应用启动后或安装完成后“补签名”来解决未知发布者。
- 不要手工只签安装器：主程序、卸载器和安装器都要签，否则更新校验和“属性 → 数字签名”会不一致。

## 2. 先选路线

| 路线 | 适用场景 | 成本/门槛 | SmartScreen |
|---|---|---|---|
| **Azure Artifact Signing**（原 Trusted Signing） | 有符合地区资格的组织，想走云签名/CI | 约 $9.99/月起；身份验证 1–30 个工作日 | 初始信任较好 |
| **OV 代码签名证书** | 普通商业发布，预算有限 | 约 $200–700/年；需硬件令牌或云 HSM | 需要声誉积累，前几天仍可能提示 |
| **EV / Sole Proprietor EV** | 想尽量缩短“未知发布者”阶段 | 更贵；通常硬件令牌；EV 多数要求企业/个体户 | 初始最好，官方说法接近即时信任 |
| **云 HSM/CA 签名服务**（eSigner、KeyLocker 等） | 不想插 USB 令牌、要 CI | 证书费 + 云签名服务费 | 取决于证书等级 |
| **自签名证书** | 仅本机/内网测试 | 免费 | **无效**，对外发布不要用 |

### 中国大陆主体的现实选择

按 2026-11 的 Microsoft 官方文档，**Azure Artifact Signing 的 Public Trust 不覆盖中国大陆主体**：

- 组织：美国、加拿大、欧盟、英国、澳大利亚、新西兰、日本、韩国、新加坡、瑞士、挪威、以色列；
- 个人开发者：仅美国/加拿大；
- Private Trust 不受地区限制，但**不能**给公网 Windows 用户建立公共信任，不适合本项目。

所以如果你是中国大陆的个人或公司，**不要先买 Azure 订阅再等资格**；优先走 CA 的 OV/EV 或 IV 证书：

- **SSL.com**：IV（个人）、OV（组织）、Sole Proprietor EV、EV；支持 eSigner 云 HSM。
- **Certum**：标准代码签名可发给个人或组织；EV 通常要求组织；有云签名方案。
- **Sectigo / DigiCert / GlobalSign**：通过授权代理购买，确认中国大陆申请主体、发票和云 HSM/令牌交付方式。

购买前问清楚这 7 件事：

1. 是否为 **Microsoft Authenticode** 代码签名证书（不是文档签名、不是 TLS）；
2. 私钥是 **硬件令牌** 还是 **云 HSM**（2023-06 起新 OV/EV 不允许裸 PFX 导出）；
3. 是否支持 **SHA-256 + RFC3161 时间戳**；
4. 证书链是否被 Windows 10/11 默认信任；
5. 是否接受你的主体（中国大陆个人/企业/个体户）；
6. 能否提供发票/合同，交付周期多久；
7. 是否支持你要用的构建方式（本机 `signtool` 或云端 API）。

> “签名”不等于“永远没有 SmartScreen 警告”。OV 需要下载/安装声誉积累；EV/云签名初始更好。不要向用户承诺零警告。

## 3. 四种落地配置

### A. OV/EV 硬件令牌（本机 Windows 构建，最直观）

把证书安装到 Windows 证书库，插好令牌，然后在 `electron-builder.yml`：

```yaml
win:
  signtoolOptions:
    # 证书 Subject 的子串；用 certmgr.msc 或下面的 PowerShell 确认
    certificateSubjectName: "Your Company Co., Ltd."
    # 与证书 Subject 保持一致（v26 用实际证书 Subject；构建后看 app-update.yml）
    publisherName: "CN=Your Company Co., Ltd., O=Your Company Co., Ltd., C=CN"
    signingHashAlgorithms:
      - sha256
    # 可选：把 jobGuard.exe 也签上（signExts 属于 win，不属于 signtoolOptions）
  # signExts:
  #   - jobGuard.exe
```

```powershell
# 先确认证书可见、未过期
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert |
  Format-List Subject, Thumbprint, NotAfter

# 如使用证书库自动发现（本项目 package.mjs 默认关闭，见 §4）
$env:CSC_IDENTITY_AUTO_DISCOVERY = "true"
pnpm package:win
```

优点：私钥不出令牌；不需要把证书文件放磁盘。
限制：构建机必须插令牌；CI 不方便；令牌驱动/中间证书要在构建机装好。

### B. PFX 文件（仅当 CA 仍提供可导出文件）

新 OV/EV 通常不再给 PFX；如果你的证书服务商明确提供 `.pfx`（或你有合规的旧证书），可以：

```powershell
$env:WIN_CSC_LINK = "C:\certs\loopsoar.pfx"
$env:WIN_CSC_KEY_PASSWORD = "[REDACTED]"
pnpm package:win
```

`electron-builder` 会自动签主程序、卸载器、安装器；**不要把 pfx/密码写进 `electron-builder.yml` 或提交 Git**。CI 用 Secret 注入。

### C. 云 HSM / CA API（eSigner、KeyLocker、SignServer 等）

云端私钥不能导出，`CSC_LINK` 不适用。用 `win.signtoolOptions.sign` 自定义钩子，让 electron-builder 对每个文件调用厂商 CLI：

```yaml
win:
  signtoolOptions:
    sign: "./scripts/sign-windows.mjs"
```

```js
// scripts/sign-windows.mjs（示意；按你的 CA CLI 替换命令）
import { execFileSync } from "node:child_process";

export default async function sign(configuration) {
  // configuration.path 是 electron-builder 当前要签的文件
  // 必须包含 RFC3161 时间戳；失败要 throw，不能静默跳过
  execFileSync("vendor-sign-cli", [
    "sign",
    "--input", configuration.path,
    "--timestamp", "http://timestamp.digicert.com",
  ], { stdio: "inherit" });
}
```

这条路线适合 CI，但要把厂商 CLI、OAuth/HSM 凭据和错误处理接好；不要用“签失败也继续打包”的脚本。

### D. Azure Artifact Signing（仅限符合地区资格的组织/个人）

`electron-builder@26` 支持 `win.azureSignOptions`：

```yaml
win:
  azureSignOptions:
    # 填证书 Subject 的完整 DN；至少 CN 要与证书一致（electron-updater 推荐完整 DN）
    publisherName: "CN=Your Company, O=Your Company, C=CN"
    endpoint: "https://eus.codesigning.azure.net"
    certificateProfileName: "loopsoar"
    codeSigningAccountName: "loopsoar-signing"
```

```powershell
$env:AZURE_TENANT_ID = "[REDACTED]"
$env:AZURE_CLIENT_ID = "[REDACTED]"
$env:AZURE_CLIENT_SECRET = "[REDACTED]"
pnpm package:win
```

注意：

- 地区资格不满足时，**不要**用 Private Trust 冒充公共信任；
- electron-builder 会安装 PowerShell `TrustedSigning` 模块，构建机需能访问 PowerShell Gallery 和 Azure endpoint；
- 首次身份验证可能 1–30 个工作日，别把它当作当天能发的方案；
- 生产 CI 优先用 Azure 联合身份/托管身份，少用长期 client secret；具体认证方式以当前 electron-builder 与 Microsoft 文档为准。

## 4. 本项目的两个坑

### 4.1 `CSC_IDENTITY_AUTO_DISCOVERY` 默认关闭

`scripts/package.mjs` 现在保留默认关闭，但允许环境变量覆盖：

```js
CSC_IDENTITY_AUTO_DISCOVERY: process.env.CSC_IDENTITY_AUTO_DISCOVERY ?? "false",
```

- 用 `WIN_CSC_LINK`（PFX）或 `azureSignOptions`：不受影响；
- 用 Windows 证书库 + 令牌、且没有显式 `certificateSubjectName`：自动发现默认关闭，builder 会跳过签名；
- 解决：配置 `certificateSubjectName`，或构建时显式设 `CSC_IDENTITY_AUTO_DISCOVERY=true`。
  默认仍是 false，不会影响未签名内测包。

### 4.2 `jobGuard.exe` 等额外 exe

主程序、卸载器、安装器由 electron-builder 自动签；`packages/shell/resources/jobGuard.exe` 是 `extraResources`，需要确认签名覆盖。可在 `win.signExts` 加 `jobGuard.exe`，打包后用 `Get-AuthenticodeSignature` 逐个检查。

## 5. v0.0.8 前的准备顺序

```text
1. 0.0.2–0.0.7 内测：不签名，Release Notes 写明未签名 + SHA256
2. 到 0.0.7 末确定发布主体、预算和证书路线
3. 申请证书/云签名账号，完成身份验证（预留 1–5 个工作日，Azure 可能更久）
4. 在 0.0.8 构建前配置 electron-builder.yml + 环境变量
5. typecheck + vitest
6. pnpm package:win（构建时自动签）
7. 验证安装包、已安装主程序、卸载器
8. 再生成/确认 SHA256SUMS.txt 与 latest.yml
9. 上传 GitHub Release；不要覆盖旧版本
10. 用上一内测版升级到 0.0.8，验证更新签名/回滚
```

### 验证

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-signature.ps1 `
  "release\dist\Loopsoar-Setup-<version>.exe"

# 已安装主程序与卸载器也要查
Get-AuthenticodeSignature "D:\Loopsoar\Loopsoar.exe" |
  Format-List Status, StatusMessage, SignerCertificate, TimeStamperCertificate

# 更严格地检查整个安装器
signtool verify /pa /all /v "release\dist\Loopsoar-Setup-<version>.exe"
```

合格标准：

- `Status = Valid`；
- `SignerCertificate.Subject` 的 CN 与发布主体一致；
- 有 `TimeStamperCertificate`（RFC3161），否则证书到期后签名失效；
- `app-update.yml` 的 publisher 与证书一致，自动更新校验能通过；
- 干净 Windows 10/11 上安装，属性 → 数字签名显示正确发布者。

## 6. 内测期发版怎么办

按当前决定：**0.0.2–0.0.7 全部内测，不签名。**

- 每个内测版仍要在 Release Notes 写“未签名，Windows 会提示未知发布者”，并提供 SHA256；
- 不要把未签名包标成“正式版”或承诺自动更新已完全可用；
- 到 v0.0.8 前再按本文第 2–5 节启动证书采购和签名配置。

这样不会为了签名把 0.0.2–0.0.7 的试用节奏卡住，也给证书验证留出时间。
