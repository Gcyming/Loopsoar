## P0-1：供应商无法保存

### 现象

设置 → 供应商，添加/编辑供应商后点击“保存并设为活跃”，右上角红色提示：

```text
Error occurred in handler for 'loopsoar:settings:upsertProvider'
too_big: Number must be less than or equal to 1000000
path: models.13.maxOutput
path: models.24.maxOutput
```

### 根因

1. `packages/contracts/src/validators.ts` 把 `ProviderModelSchema.maxOutput` 上限写死为 `1_000_000`，但上游模型元数据常见 `1_048_576`（二进制百万）；合法配置在保存时被 schema 拒绝。
2. `Settings.tsx` 的模型表把上下文/输出显示成 `K`，保存时 `Number(value) * 1000`；`1_048_576` 显示成 `1049`，一旦编辑回写就变成 `1_049_000`，进一步越过旧上限；用户按“token”填 `1000000` 还会被乘成 `1_000_000_000`。
3. UI 没有保存前的 token 上限校验，用户只能看到裸 IPC 校验错误，无法知道是哪一个模型、应该怎么改。

### 修复

- `ProviderModelSchema.contextWindow` / `maxOutput` 统一使用 `PROVIDER_MODEL_TOKEN_LIMIT = 10_000_000`；兼容 `1_048_576`，仍拦截明显异常值。
- 模型表输入改为**实际 token 数**，取消 `* 1000` 和 `Math.round(/1000)` 转换；表头为“上下文（tokens）/输出（tokens）”，并增加单位提示。
- 保存前调用 `findProviderTokenLimitIssue`，定位到具体模型和字段，弹出可操作的中文/英文提示，不再把 Zod `too_big` 直接暴露给用户。
- 新增回归：
  - `tests/contracts/providerModelLimits.spec.ts`
  - `tests/ui/providerTokenLimits.spec.ts`

### 验证证据

- 真实打包版 `Loopsoar 0.0.1`（portable app + CDP）保存 `contextWindow/maxOutput = 1_048_576` 与 `10_000_000` 成功，`providers.json` 原样持久化。
- 在安装版设置弹窗中点击“保存并设为活跃”，右上角显示“供应商已保存并设为活跃（含模型参数）”。
- 将输出改为 `10_000_001` 后保存，弹窗保持打开并显示：
  `模型「model-1m」的输出（tokens）为 10,000,001，超过允许的 10,000,000 tokens。请填实际 token 数（不是 K）。`
- 打包版 smoke：诊断包导出、数据备份导出、终端打开/执行均成功。

## P0-2：安装器无法从 `release/dist` 启动

### 现象

双击 `release/dist/Loopsoar-Setup-0.0.1.exe`（或从该目录用 `/S` 静默安装）时，NSIS 在解包阶段弹出：

```text
NSIS Error
Error writing temporary file. Make sure your temp folder is valid.
```

静默安装返回码 `2`，目录里不会产生任何安装文件。复制到普通目录后同一个 exe 能正常安装，说明安装包本身不是损坏的。

### 根因

`D:\tool\AI\real-project\Loopsoar` 项目容器（以及继承它的 `Parent file/release/dist`）带有：

```text
Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)
Everyone:(CI)(DENY)(DC)
```

安装器以 Low 完整性令牌运行，NSIS 解包到 Medium 完整性的 `%TEMP%` 时被 `NO_WRITE_UP` 拦住，于是报“临时目录不可写”。这不是 NSIS 或 electron-builder 的 bug，而是项目目录的 ACL/完整性标签被错误设置；任何从该目录直接运行的可执行文件都可能踩到。

### 修复

- 已先备份 ACL 到 `C:\Users\MR\AppData\Local\hermes\cache\scratch\loopsoar-container-acl-backup.txt`。
- 对项目容器递归移除 `Everyone` 的 DENY ACE，并把完整性标签统一为 `Medium`：
  ```powershell
  icacls 'D:\tool\AI\real-project\Loopsoar' /remove:d Everyone /T /C
  icacls 'D:\tool\AI\real-project\Loopsoar' /setintegritylevel '(OI)(CI)Medium' /T /C
  ```
- 复核：项目根、`Parent file`、`release/dist`、`Setup.exe` 均为 `Medium Mandatory Level`，不再有 `DENY`；安装器从 `release/dist` 静默安装到 `D:\LoopsoarTestFix4` 返回 `0`。
- 安装器的目标目录预检仍有效：把目标指向 Low Mandatory Level 目录时，静默安装返回 `2` 且不落文件；正常目录返回 `0`。
